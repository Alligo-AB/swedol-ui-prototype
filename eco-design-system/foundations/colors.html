Foundations

Colors

Color in ECO is semantic. A token says what a color is for, not what it looks like, so text, surfaces, borders and status each have their own family and a component never needs a raw hex value.

Here in the color section you’ll find the colors of ECO that serve as the foundation for the majority of surfaces, borders and more, acting as essential components of our visual identity.

OverviewPrimitive colorsSemantic tokens

Overview

In our UI, colors are applied according to their specific function. These functions are called semantic colors and describe the color categories we use. They derive from our base colors, the primitive colors, which serve only as references and are never used directly in the UI.

If you need a color beyond the semantic colors, consult a designer to evaluate whether the palette should be extended. ECO is built for consistency and efficiency, so always use the provided guidelines without altering or extending the styles.

This documentation has three pages. Overview (this page) explains how color works in ECO. Primitive colors lists the base palette. Semantic tokens lists every token the components use, as cards or as a table.

Semantic colors

Semantic colors are associated with particular meanings and are used directly in the user interface.

Semantic colors help the users of the design system create consistency by giving them a collection of self-documenting tokens. The tokens can be applied across different UI components, instead of picking at random from a broad range of neutral colors.

By using tokens to define and categorize roles instead of relying on hex values, any change to the color palette is reflected systematically. A change to one color then cascades consistently to every role that uses it.

Primitive colors

Primitive colors are our base palette, which the semantic palette derives from. A primitive is a color with a name, and the name derives from the hex code. They are references only: a component never uses one.

  • Neutral (grey): black, white and a ladder of greys. The foundation of the UI.
  • System: the colors of messages and status.
  • Concept brand colors: the accent of each Alligo concept brand.
  • Text emphasis and opacity: the colors the text tokens and the overlays derive from.

How color tokens work

Tokens start as primitive values, which have a name that derives from a hex code. In production we use the semantic tokens, which derive from the primitive tokens. The name of a semantic token describes how and where it should be used.

Naming

  • A primitive is --color-primitive-color-<group>-<name>, for example neutral-grey-90.
  • A semantic token is --color-<role>-<name>, for example surface-action-2 or text-primary.
  • The role comes first: surface, text, icon, border, accent. Status and state come after it.

Pick the token by role, not by how it looks. Each family has its own section on the Semantic tokens page.

Online vs traditional

The colors divide into main and complementary colors, which together represent the visual identity. Swedol, for example, is primarily perceived as a black and lime green company, while Tools is white and red. To make that visible online we use, for example, a dark header for Swedol and a lighter touch for Tools.

Traditional media

Black is generally the base color for the whole Alligo group and is used on larger surfaces. It represents professionalism and puts competence in what we do.

E-com

The colors for e-com are weighted towards a lighter, white base. White is a proven color for creating higher online sales and for mediating a positive user experience.

Contrast ratios

Contrast is the difference in brightness between two elements. The Web Content Accessibility Guidelines (WCAG) set the ratios that give the minimum contrast for legibility.

Large text is 18 point (typically 24px) or larger, or 14 point (typically 18.66px) or larger when it is bold. The swatches of the text tokens on the Semantic tokens page show the ratio on the intended surface.

Usage

Do

  • Write var(--color-…). Look the name up in tokens.json.
  • Pick the token by role (text, surface, border, status), not by how it looks.
  • Use inverted text and icon tokens on dark surfaces.
  • Keep status colors for status: information, success, warning, danger.

Don’t

  • Hardcode hex or rgb, even when it matches a token today.
  • Use a primitive color in a component.
  • Use the brand accent as text color on white.
  • Put light-mode tokens on a dark surface.
  • Invent a new grey. If nothing fits, ask before adding a value.
