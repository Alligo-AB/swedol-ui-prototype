Docs cards

Two card layouts for the documentation pages: a Foundations card with a small live picture of a token, and a Components card with a working ECO component inside it. Both are made of the docs card (.ds-card).

They are documentation items, not product components. They are still being built: the layout may change.

Overview

Use a docs card to send the reader from a hub page (a start page, an overview) to a page about one subject. The picture in the top of the card shows the subject, so the reader sees what it is before reading. Both layouts have the same parts: visual, title, description. They differ in what the visual is and in what is clickable.

Which layout

Foundations cardComponents card
SubjectA foundation or a token group: colors, typography, spacing, elevation, motionA component the reader can try: button, switch, checkbox, input
VisualA small picture built from the tokens (static or one movement on hover). It is decoration: aria-hiddenThe real ECO component, working. It is content the reader can use
ClickableThe whole card is one link (a.ds-card)Only the action link at the bottom (div.ds-card). The component in the visual must stay clickable, and a link cannot contain controls
HoverBorder darkens, the picture can move (the dot)The component reacts as itself. The card does not change
info

Use six cards or fewer in a set, in the grid of .ds-cards (1 column, 2 from 640px, 3 from 1024px). Every card in a set has the same layout.

Foundations card

The whole card is a link. The visual is built from the tokens it describes, so it cannot drift from the system. Hover or focus a card: the dot moves.

Anatomy

  1. 1

    Card: a.ds-card. The whole card is the link, with the hover border and the focus ring of docs.css.

  2. 2

    Visual: .ds-card__visual with aria-hidden="true". One small picture from the tokens: .mini-swatches, .mini-type, .hx-cols, .hx-space, .hx-elev or .hx-track with .hx-dot.

  3. 3

    Title: .ds-card__title, one to three words.

  4. 4

    Description: .ds-card__desc, one sentence.

Usage

  
    
    
  • Do not put a control inside a Foundations card. The card is a link, and a link must not contain buttons or inputs.
    • 
    
  • Do not make a Components card a link. Use the action link.
    • 
    
  • Do not mix the two layouts in one grid.
    • 
    
  • Take every visual from tokens and shared component CSS. A picture that has its own hex or pixel values drifts from the system.
    • 
    
  • Keep the live component small: one or two states, no more than the visual can hold at 375px.
    •
