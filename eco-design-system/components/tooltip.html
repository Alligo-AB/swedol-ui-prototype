Overview
Tooltips are typically documented as part of the components they belong to, rather than as standalone components. The only exception is the Definition Tooltip, which has its own documentation.
They provide additional information when a user hovers over a UI element and should only be used when necessary to offer quick context without cluttering the interface.
Anatomy
  1. Container. The box that holds the label. Surface 100 at 90% opacity, with an elevation shadow.
  2. Label. Short text, one to three words, that names the trigger. Breuer Condensed, regular.
  3. Caret. The beak. It points at the center of the trigger and sits 4px from it. Only the Body type has none.
  4. Trigger. The element the tooltip belongs to, usually an icon button. The tooltip shows when the user hovers it.
When to use
Most components, such as Icon Buttons, Icon Tabs, Sliders, and Copy Buttons, already include built-in tooltips. In most cases, there is no need to add a tooltip separately. While customization is possible, it is generally not recommended.
Use tooltips to:
  • Show the name of a control that does not have a visible label
  • Provide helpful information about a focusable element
  • Give additional context or explanation when needed
  • Define a term or explain an inline item using a Definition Tooltip
Definition Tooltip
A Definition Tooltip is used to explain terms or provide additional help within text. It is especially useful for labels, words in paragraphs, and compact interfaces such as data tables, where adding extra icons could create visual clutter.
When not to use
For critical information
Do not use tooltips for important information that users need to complete a task. Since tooltips disappear when users move away from the element, they can be easily missed. Use always-visible helper text instead, especially for important instructions or required fields.
For interactive content
Do not place interactive elements, such as buttons, links, or images, inside a tooltip. Tooltips cannot receive focus and may be difficult or impossible for some users to interact with.
If users need to interact with additional content, use a Toggletip (TBA) instead. Toggletips support proper focus management and keyboard navigation, providing a more accessible experience for all users.
Positioning
Alignment
The tooltip container can be aligned to the start, center, or end of its trigger element. This helps keep the tooltip visible and prevents it from covering important content.
The trigger and caret should be vertically aligned to clearly show their connection, especially when multiple interactive elements are placed close together.
Placement
By default, tooltips use auto placement. When opened, they automatically adjust their position to stay within the viewport and avoid being cut off.
Tooltips can also be positioned on the top, right, bottom, or left side of the trigger element. Always ensure the tooltip remains visible and does not cover content that is important for the user’s task.
For definition tooltips, avoid covering the surrounding text, especially the words immediately before and after the trigger word.
When active, the tooltip should appear above other content and remain fully visible without being clipped by nearby components or extending beyond the viewport.

Automatic alignment
Top and Bottom tooltips are automatic by default: centered on the trigger. When a centered tooltip would leave the viewport sideways it aligns to the start or the end instead, exactly as the Start and End examples under Positioning: the beak sits 16px from the tooltip's edge and on the center of the trigger, so the tooltip lines up with the trigger's outer edge. tooltip.js adds tooltip--align-start or tooltip--align-end for this. Above or below is handled by components/js/tooltip.js: when a Top or Bottom tooltip opens with too little room on its side and more on the other, it flips (tooltip--flip), beak included. A page with a sticky header sets --tooltip-safe-top (its height) so room above counts from below the header. CSS alone cannot do this: a browser picks a flip from the layout-time scroll position, which is wrong on a page that scrolls. Without the script a tooltip stays on its declared side. Add tooltip--manual to keep a tooltip fixed and centered. It uses CSS anchor positioning and the tooltip becomes position: fixed, so a clipping container cannot cut it off. Where anchor positioning is not supported, the tooltip stays centered as in manual mode. The other types (start, end, left, right) are always manual.

Behavior and accessibility
TopicRule
TriggerHover over the wrapper (.tooltip-wrap:hover). Never on :focus.
Namearia-label on the button with the same text as the tooltip. The tooltip itself is not announced.
PlacementChoose by room: Bottom in toolbars, Top in table rows.
WidthOne line when the text fits, otherwise it wraps at max-width: min(280px, 100vw − 16px): never wider than 280px and never wider than the viewport minus the 8px edge margin. The tooltip is width: max-content, so a short label is as wide as its text. Keep the text to 1–3 words: a tooltip that wraps is a sign the text belongs in helper text.
Layerz-index: var(--tooltip-z, 300), elevation-b-40 shadow. A page with a sticky header sets --tooltip-z below the header’s z-index on :root, so a tooltip never paints over the menu.
AlignmentTop and Bottom are automatic by default (tooltip.js aligns them to the start or end at a viewport edge, and flips them above or below when there is no room). Add tooltip--manual for a fixed, centered tooltip. Start, end, left and right are always manual.
Positioning contextAutomatic tooltips are position: fixed, so a container with overflow does not clip them. A transform, filter or contain on an ancestor makes fixed relative to that ancestor: use tooltip--manual there.
Own positioning scriptA page must not position a tooltip with a script of its own (for example inline left): the script and the automatic alignment would fight over the position. Use data-tooltip, or tooltip--manual if a fixed tooltip is really needed.
Browser supportAutomatic alignment uses CSS anchor positioning. Without support the tooltip stays centered, as in manual mode.
Open point: keyboard focus. The tooltip is shown on hover only, and this page says never on :focus (here, in States and in Usage). The Overview guidance says to use tooltips for “helpful information about a focusable element”, which can imply showing it on focus. To be decided.


Code


Add a tooltip to a page


Link the shared files once per page. Never copy the rules, and never write a tooltip script of your own: a page that does (for example a row-tooltip) fights the shared one over the position.


StepWhat to do


1. Link<link rel="stylesheet" href="/components/css/tooltip.css"> and <script src="/components/js/tooltip.js"></script>. Both templates (template.html, mypages/mypages-template.html) already have them.


2. ChooseGlobal (recommended for icon buttons, table rows and anything built in JS): add data-tooltip="Label" to the element. Markup (.tooltip-wrap + .tooltip): when you need a specific type or size (start, end, left, right, Large, Body), or a tooltip that is part of the page markup.


3. Name the controlGive the button an aria-label with the same text as the tooltip. The tooltip itself is not announced.




Global tooltip: data-tooltip


One shared tooltip is shown for any element with data-tooltip, including elements you add later. It is a popover in the top layer, so no overflow, z-index or stacking context can clip it or hide it. It is centered on the element, aligns to the start or end of it (as under Positioning) when it would leave the viewport sideways, and flips above or below when there is no room.


SettingEffect


data-tooltip="Label"The text. Plain text only, one to three words.


data-tooltip-position="bottom"Below the element. Default is above (top). Use Bottom in toolbars (room below), Top in table rows (room above). The flip still applies.


--tooltip-safe-top on :rootHeight in px of a sticky header. Room above then counts from below the header, so a tooltip is flipped below instead of landing on it. Set it from the breakpoint where the header sticks.


--tooltip-z on :rootz-index of tooltips in markup (.tooltip-wrap), default 300. Set it below a sticky header's z-index. The global tooltip is in the top layer and does not use it.




Hover the buttons: the first uses data-tooltip, the second adds data-tooltip-position="bottom".


Markup tooltip: .tooltip-wrap


Classes name where the tooltip sits next to the element: tooltip--top and tooltip--bottom (automatic), --top-start, --top-end, --bottom-start, --bottom-end, --left, --right, --left-start, --right-start and --body (always manual). tooltip--lg is Large. tooltip--manual keeps a Top or Bottom tooltip fixed and centered, and tooltip--flip, tooltip--align-start and tooltip--align-end are added by tooltip.js: never write them yourself.


Things to know


    

  • Hover only, never on keyboard focus. On touch it shows on tap and hides on the next tap elsewhere.
    • 

  • Automatic alignment and the global tooltip use CSS anchor positioning. In a browser without it the tooltip is centered on the element by script and kept inside the viewport.
    • 

  • Without tooltip.js a markup tooltip stays on its declared side, and a data-tooltip shows nothing.
    • 

  • A transform, filter or contain on an ancestor makes a markup tooltip's fixed position relative to that ancestor. The global tooltip is not affected. Use tooltip--manual if you must keep a markup tooltip there.
    • 

  • Replacing an old script: delete the page's own tooltip script and CSS (.row-tooltip, a local .tooltip block), keep the data-tooltip attributes, and add data-tooltip-position="bottom" where the old one opened below.
