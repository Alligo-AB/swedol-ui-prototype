Notifications

Notifications tell users that something changed. Five components cover it, from a toast that vanishes in four seconds to a modal that stops the page. The skill is choosing the right one, and as quiet a one as the situation allows.

The five components

Two origins. Task-generated notifications answer something the user just did and belong next to where they are working. System-generated ones come from the application or an administrator, independent of what the user is doing.

When not to notify

Every notification interrupts. Frequent interruptions lower productivity and cause alert fatigue, so keep each one inside the part of the interface and the task where it matters. If the message is not needed, do not send it.

Status and icon

Status colors carry a fixed meaning, and each has one reserved icon. Never pair a status color with another status’s icon. Icons are Material Symbols Outlined, weight 300, filled.

E-Com (E-Com Toast, E-Com Modal) uses the brand’s black and white and no status color; any icon from the gallery may be used. Promotion banners use the brand’s accent color or neutral black and white, also with a free icon.

Choosing the emphasis

Weak is the default. Strong is used sparingly. Status says what the message is (color and icon). Emphasis says how loud it is. Choose the component first, then the status by its meaning, then the emphasis. The status does not decide the emphasis; the consequence does. An Error does not have to be Strong, and a Warning can be Strong if the consequence is serious.

Design guidance given 2026-10-13, not in Figma. Figma defines the tiers but not when to pick which. It agrees with the Banner guidance already here (Strong only for what is urgent, Weaker for general information) and with how Carbon, Adobe Spectrum, SAP Fiori, Material treat routine confirmations. It does not cover Inline: the Inline row is a recommendation.

Weak or Strong for a warning or an error

Weak: an ordinary warning or error that can be handled locally, such as a failed action that can be tried again, or something the user must correct. Strong: a critical outage, a blocked main flow, risk of data loss, or anything that needs immediate attention.

A toast disappears

If the message must be noticed, must stay, or needs an action, it does not belong in a toast. Show it as a Banner, or near the affected content. For critical or blocking information choose a persistent notification type; do not make a temporary toast louder.

Which one

Ask in this order and take the first yes.

  1. Is it normal feedback on something the user just did? Including “Could not save – try again”. Toast, Weak.
  2. Must the user notice it, act on it, or be able to read it again? Not a toast. An Inline notification near the content, or a Banner.
  3. Is it general information or an offer? Banner, Weaker.
  4. Is it an ordinary warning or error that can be handled locally? Weak.
  5. Is it a critical outage, a blocked main flow, risk of data loss, or does it need immediate attention? Strong. A Banner; a Toast only exceptionally.

Rules

  • Set the emphasis on purpose, and keep the same situation at the same emphasis across the product.
  • One loud message at a time. Never stack Strong banners. Campaigns use the Promotion banner, not a higher emphasis.
  • Emphasis is never the only signal. The icon and the text always carry the status; color and tint only add to it.

Dismissing

A notification that does not go away on its own must always be dismissable. A Modal must support all three ways: ×, ESC and a click outside.

On a Banner, whether the × exists is decided by the administrator or content owner, not by the component.

Usage

Do

  • Keep task feedback close to where the user is working.
  • Choose the least disruptive component that does the job.
  • Match status icon and status color.
  • Give errors a way forward: a retry, a fix, a link.

Don’t

  • Use a banner or modal for feedback on a click.
  • Notify when nothing the user cares about changed.
  • Use a notification for a single form field: use the field’s own message.
  • Show several notifications at once for the same event.
