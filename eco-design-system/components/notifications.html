Notifications

Notifications tell users that something changed. Five components cover it, from a toast that vanishes in four seconds to a modal that stops the page. The skill is choosing the right one, and as quiet a one as the situation allows.

Decision matrix

Two origins. Task-generated notifications answer something the user just did and belong next to where they are working. System-generated ones come from the application or an administrator, independent of what the user is doing.

When not to notify

Every notification interrupts. Frequent interruptions lower productivity and cause alert fatigue, so keep each one inside the part of the interface and the task where it matters. If the message is not needed, do not send it.

Status and icon

Status colors carry a fixed meaning, and each has one reserved icon. Never pair a status color with another status’s icon. Icons are Material Symbols Outlined, weight 300, filled.

Without a status

E-Com (E-Com Toast, E-Com Modal, Informational E-Com inline) uses the brand’s black and white and no status color; any icon from the gallery may be used. Promotion banners use the brand’s accent color or neutral black and white, also with a free icon.

Dismissing

A notification that does not go away on its own must always be dismissable. A Modal must support all three ways: ×, ESC and a click outside.

Usage

Do

  • Keep task feedback close to where the user is working.
  • Choose the least disruptive component that does the job.
  • Match status icon and status color.
  • Give errors a way forward: a retry, a fix, a link.

Don’t

  • Use a banner or modal for feedback on a click.
  • Notify when nothing the user cares about changed.
  • Use a notification for a single form field: use the field’s own message.
  • Show several notifications at once for the same event.
