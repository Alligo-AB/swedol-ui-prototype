Button

A button triggers an action or takes the user to another page. It lets the user make a choice with a single tap. Use a mix of styles on one page to point at the main action and still offer the alternatives.

Tokens, sizes, measurements, states and requirements. Values come from the live token package and from Figma: Button, Icon buttons, Button dot & badges.

States

Button

Every state for every variant. Hover and focus are forced on this page with data-state so they show at the same time; in your code they come from :hover and the keyboard focus rule. The buttons are live (the disabled ones do not respond).

What each state means

StateDescription
EnabledThe standard state of a button: it is available for interaction and is not currently selected. It includes Hover and Focus of the button type.
HoverShown when the user hovers the cursor over the button, to show that the component is interactive.
FocusThe visual style shown when the button is reached with the keyboard (often with Tab). It shows that the button is ready to be activated. It is a blue outline (border-focus), so users can move through the interface without a mouse.
DisabledA disabled button prevents interaction: hover, focus and click. It is not focusable, so Tab skips it. Screen readers may still announce it as unavailable when the user browses the page. Do not associate a tooltip with a disabled button.
SelectedUsed by the System button in some cases. A selected button has been actively chosen, toggled on, or is the item currently in focus within a group of options. It shows which option is active and confirms that the user’s action was registered.

Width

A button hugs its content. An icon-only button is a square. Full width comes from the page layout, not from a modifier.

Behavior

InputResult
Click, Enter, SpaceRuns the action. Use <button> for actions and <a class="btn …"> for navigation.
Tab / Shift+TabMoves between buttons. The focus ring shows only when body.keyboard-nav is set (on Tab, removed on mousedown and touchstart), the same as the form controls.
DisabledUse the disabled attribute. It is not focusable and has no hover. Say why in nearby text when the reason is not obvious.
System selectedSet aria-pressed="true". It is a toggle, so it must not be used for page navigation.
Icon onlyAdd aria-label, and hide the icon with aria-hidden="true".
LabelUppercase through CSS, so write it in sentence case in the HTML. Keep it short and start with a verb.
Icon only tooltipAlways with a tooltip, shown after a 300ms hover delay (design guidance). Open point: the shared tooltip (components/js/tooltip.js) has no hover delay yet, so it appears at once. Never on a disabled button.

Accessibility Requirements

TopicRequirement
ElementA native <button type="button"> for an action, an <a class="btn …"> for navigation. Never a div with a click handler.
NameA visible label, or an aria-label on an icon-only button. A badge is aria-hidden="true": put the count in the aria-label.
Focus2px ring border-focus with a 2px gap, on keyboard use (WCAG 2.4.7, 1.4.11). It is set with body.keyboard-nav, never :focus-visible.
StateSystem selected is aria-pressed. A disabled button uses the disabled attribute.
Target sizeThe smallest button is 32px high; Close is 24px, which meets WCAG 2.5.8 (24px) but is below the usual 44px touch target.
ContrastChoose standard or inverted variants by context, visibility and contrast, not by background color alone. Disabled tokens are exempt from contrast requirements.
