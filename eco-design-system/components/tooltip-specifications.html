Tooltip

A tooltip gives an icon-only button a short name when the user hovers it or moves keyboard focus to it. Esc hides it.

Tokens, sizes, spacing, states and requirements. Values come from the live token package and from Figma: Tooltip.

States

Two triggers: hover and keyboard focus (:focus-visible) fade the tooltip in over duration-fast-2 with ease-standard. The tooltip has pointer-events: none so it never gets in the way.

Width

One line when the text fits, otherwise it wraps at max-width: min(280px, 100vw − 16px): never wider than 280px and never wider than the window minus the 8px edge margin. The tooltip is width: max-content, so a short label is as wide as its text.

Behavior

Automatic placement

Top and Bottom tooltips are automatic by default. components/js/tooltip.js and CSS anchor positioning do the work:

  • The tooltip is centered on the trigger.
  • When a centered tooltip would leave the viewport sideways it aligns to the start or the end instead, as the Start and End examples under Layout & Appearance: the beak sits 16px from the edge of the tooltip and on the center of the trigger, so the tooltip lines up with the outer edge of the trigger. The script adds tooltip--align-start or tooltip--align-end.
  • When the tooltip opens with too little room on its side and more on the other, it flips above or below, beak included (tooltip--flip). CSS alone cannot do this: a browser picks a flip from the layout-time scroll position, which is wrong on a page that scrolls.
  • A page with a sticky header sets --tooltip-safe-top (the height of the header), so room above counts from below the header.
  • Add tooltip--manual to keep a tooltip fixed and centered.
  • The tooltip is position: fixed, so a clipping container cannot cut it off. Where anchor positioning is not supported, the tooltip stays centered, as in manual mode.
  • The other types (start, end, left, right) are always manual.

Accessibility Requirements

TopicRequirement
TriggerHover over the wrapper (.tooltip-wrap:hover) or keyboard focus on the trigger (:focus-visible, not the focus a mouse click gives). Esc hides it without moving focus (WCAG 1.4.13 dismissible).
Namearia-label on the button with the same text as the tooltip. The tooltip itself is not announced.
TextOne to three words. No information the user needs to complete a task: it disappears when the pointer moves away.
Interactive contentNone. A tooltip cannot take focus, so it never holds a button, link or image. Use a Toggletip (TBA).

Open point: hoverable (WCAG 1.4.13). The tooltip has pointer-events: none, so the pointer cannot move onto it to read it. Persistent and dismissible are met (it stays until the pointer or focus leaves, Esc hides it). Hoverable would need a pointer-reachable tooltip, which conflicts with “never in the way”. To be decided.
