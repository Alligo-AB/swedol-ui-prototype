Overview
Tabs organise content across screens, data sets and interactions at the same level of hierarchy. A tab bar lets the user move between groups of related content without leaving the page. For content that must be read in order, use steps instead.
Tabs come as Primary and Secondary, in three sizes, with a label, a label and an icon, or an icon only, and with an optional status dot or number. A bar either switches panels on the same page (content tabs) or links to other pages (navigation tabs).
This documentation has three pages. Examples & Guidelines (this page) shows when and how to use tabs. Specifications holds the values: tokens, sizes, states and requirements. Code shows how to add a tab bar to a page.




Usage
When to use
Use tabs to organise content at the same level of hierarchy. They control the region shown below them. Use them to:
  • Move between pages or sections at the same level, as sub-navigation (for example the My Pages account menu)
  • Separate related content inside an area, such as a card, a sheet or an information pane
  • Show product information in groups: overview, details, reviews, support

When not to use
For content that must be read in order
Use a stepper (steps) when the user goes through content in a fixed order. Use eco-pill-segment-control to switch between two to four views or filters of the same content (a fixed, small number: with more options, or a number that can grow, use tabs), a button group for joined options in a toolbar, and eco-radio for a choice that is submitted.
For more than two levels
Secondary tabs go below primary tabs, never above, and a page does not nest more than two levels.
Keep labels short
Tab labels sit in one row. A few short labels are read at a glance; long labels make the bar scroll sideways and hide tabs.

Do
  • Group content at the same level of hierarchy.
  • Put secondary tabs below primary tabs, never above.
  • Keep labels short, in one row. Prefer scrollable tabs for long titles.
  • Use only globally known icons for icon-only tabs, with an aria-label.
Don’t
  • Use tabs for content that must be read in order.
  • Nest more than two levels of tabs.
  • Make a tab with a click handler on a div.
  • Copy the CSS into a page: link tabs.css.




Anatomy
Tab bar
  1. Tab. A button (content tabs) or a link (navigation tabs). Primary tabs have 24px between them; Secondary tabs have 16px padding on each side.
  2. Icon and label. An optional 20px icon above an uppercase label. A label can also have a leading 24px icon. An icon-only tab needs an aria-label.
  3. Active line. Under the active tab: 3px on Primary, 2px on Secondary. It slides to the clicked tab. Black by default, or the accent colour.
  4. Status. A red dot or a red number after the label, 4px away. It marks something new, or says how many.
  5. Divider. A 1px line under the whole bar. It runs the full width, also when the bar scrolls.




Variants
Breakpoint
Primary and Secondary
Primary tabs are placed at the top of a content page, as sub-navigation when the main navigation needs more levels, or as top-level navigation where there is none (for example campaign pages). The line spans the label, 24px between tabs. Secondary tabs are always placed below primary tabs, if any. They separate related content inside an area (a card, a sheet, an information pane, sections on one page). Each tab has 16px side padding, so the line is wider than the label.
Content
Label only, label with an icon above it, or icon only. Use standalone icons only when they are globally well known, and give each an aria-label.
Status and leading icon
A red dot marks something new in a tab. A red number badge says how many. Both sit after the label, 4px away. On an icon-only tab the dot sits at the icon’s top right. An icon can also lead the label: 24px, or 20px on Small below 769px.
On a grey surface
Background Colored in Figma: the hover line is surface-40 instead of surface-10, so it stays visible on grey. Add .tab-bar--on-grey.
Accent colour
The active line is black by default. Where a product uses its accent colour, set --tab-line-active on the bar. Swedol uses --color-accent-default; Tools is a primitive in the package (--color-primitive-color-brand-tools-accent-brand). Primary and Secondary tabs, content tabs and link tabs all follow it; the grey hover line does not change. Click a tab to see the line slide in the accent colour.
Many tabs
Tab labels appear in one row. Scrollable tabs are preferred when the titles do not fit: the bar scrolls sideways and the divider line runs the full width. Drag or scroll the bar below.
On-page navigation
Secondary tabs can navigate a whole page. Each tab is a link to a section: the bar sticks to the top, the line follows the section in view, and a click scrolls to the section. The page can have as many sections as it needs: the bar scrolls sideways and keeps the current tab in view. Add tab-bar--page, and scroll the page below or click a tab.




Sizes
Large, Medium and Small. Below 769px the labels are 16/16 (Large, Medium) and 14/14 (Small); from 769px 18/18 and 16/16. Large and Medium differ only in the gap to the line on mobile. Measurements are under Sizes in Specifications.

Layout & Appearance
Placement
Primary tabs go at the top of a content page. Secondary tabs go below them, inside the content area they control. The bar is as wide as its container.
Overflow
The bar scrolls sideways with the scrollbar hidden, and the active tab is scrolled into view. The divider runs the full width. The overflow “more” button is not built yet.
Appearance
Labels are uppercase Breuer Condensed. The active tab has a black label and a black line; hover gives a grey line. Token names and values are under Design Tokens in Specifications.




Behavior
Switching
A click on a tab, or arrow-key focus, opens that tab. On content tabs the active line slides to the clicked tab. On navigation tabs the line slides across the page change.
On-page navigation
With tab-bar--page the tabs are links to sections of the page. The line follows the section in view as the page scrolls. A click scrolls to the section (150 to 450 ms by distance, ease-decelerate-generic, instant under reduced motion), moves focus to it and adds the #hash to the address. The number of sections is not limited. Details are under Behavior in Specifications.
Hover and focus
Hover gives a grey 3px line and greys the label and the icon. Focus is a 2px ring around icon and label, on an enabled or an active tab alike; the line stays visible below it. All states are listed under States in Specifications. Figma has no disabled state, so none is built.
Motion
The sliding line uses duration-medium-2 with ease-standard and is off under reduced motion. Details are under Motion in Specifications.




Accessibility
All requirements are listed under Accessibility Requirements in Specifications.
Keyboard support
Tab moves into the bar. Left and Right switch tab (they wrap), Home and End go to the first and last. A tab opens as soon as it is focused. tabs.js does this.
Screen reader support
Content tabs use role="tablist", role="tab" with aria-selected and aria-controls, and role="tabpanel" with aria-labelledby. Navigation tabs are links in a nav, with aria-current="page" on the current one. An icon-only tab needs an aria-label.
