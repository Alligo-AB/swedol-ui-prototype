Toast

A toast is short-lived feedback on something the user just did: saved, copied, failed. It slides in, says its piece and leaves without blocking the page.

Every example is the real component, and every “Show toast” button fires a real toast in the corner of your window. Not sure it is the right component? Start at the notification guide. Specification: .claude/skills/eco-toast-system/SKILL.md.

Variants

    
Four statuses in two emphasis levels, each with a Default and an Actionable layout. The status decides the color and the icon; the emphasis decides how loud the toast is.

    
Breakpoint
      

    
Strong and Weak

    
Strong has a tinted background and is the default. Weak is white with the status color in the 2px left edge only.

    

    
Actionable

    
Add buttons and an optional text link below the text, indented 32px to line up under it. Use it when the user needs a way forward, such as Retry after an error.

    

    
Actionable with inline links

    
The action area holds either buttons or inline links, not both. Use links for lighter choices such as Undo or Learn more.

Usage

    
Notifications look alike but differ in how much they interrupt. Choose by what the user needs to do.

    
The message…Use

    

      
Do
  • Confirm what happened in a few words: “Folder created”.
  • Match the status icon to the status color.
  • Put a Retry button inside an error toast.
  • Run the exit animation on every dismissal.

      
Don’t
  • Use a toast for a single form field. Use the field’s error message.
  • Put a permanent message in a toast. Use Inline or Banner.
  • Ask for confirmation in a toast. Use a Modal.
  • Stack several toasts. One at a time.
