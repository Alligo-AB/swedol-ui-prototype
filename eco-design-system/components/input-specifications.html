Input

An input field lets the user enter free text, numbers or search terms. It can have a label, a left icon, right-hand action icons and a message that explains or validates the value.

Tokens, sizes, measurements, states and requirements. Values come from the live token package and from Figma: Base Input.

Right-hand icons are 20px in every size, but the component that holds them differs. A Button (eco-button, Blank, icon only, 6px padding = 32px, grey fill on hover) holds them on Desktop Large, Desktop Small and Mobile Large. An Icon Button (just the 20px icon, it turns grey on hover) holds them on Desktop XSmall and Mobile Small. Icon color is text-action-primary. Padding top and bottom comes from the fixed height. The 6px values and the 10px gap before the icons on Mobile Large are literals: there is no spacing token for them.

Behavior

InputResult
Type a valueThe field becomes Active: black border and the clear button appears.
Clear buttonEmpties the field and returns focus to it. It is a real button with an aria-label.
TabThe blue ring shows on keyboard focus only (body.keyboard-nav, set by a small script).
Hover on a right iconButton: grey fill (surface-opacity-black-05). Icon Button: the icon turns text-action-primary-hover.
DisabledNot focusable. Grey fill, light border, text-disabled for text, icons and message.

Accessibility Requirements

TopicRequirement
LabelAlways a label with for and id. Search fields without a visible label need an aria-label.
ErrorSet aria-invalid="true" and point aria-describedby at the message.
Icon buttonsReal button elements with an aria-label. The decorative icons are aria-hidden="true".
FocusA 2px ring on keyboard focus (border-focus), not on mouse click (WCAG 2.4.7, 1.4.11).
ColorError and success are not shown by color alone: the message says it, and an icon helps.
DisabledNot focusable. Disabled tokens are exempt from contrast requirements.

Open point: multi-line text fields are a separate component: see Text area.
