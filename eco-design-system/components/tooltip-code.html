Tooltip

A tooltip gives an icon-only button a short name when the user hovers it or moves keyboard focus to it. Esc hides it.

How to add a tooltip to a page. The files are components/css/tooltip.css and components/js/tooltip.js.

Examples & GuidelinesSpecificationsCode

Basic Usage

Link the shared files once per page. Never copy the rules, and never write a tooltip script of your own: a page that does (for example a row-tooltip) fights the shared one over the position.

StepWhat to do
1. Link<link rel="stylesheet" href="/components/css/tooltip.css"> and <script src="/components/js/tooltip.js"></script>. Both templates (template.html, mypages/mypages-template.html) already have them.
2. ChooseGlobal (recommended for icon buttons, table rows and anything built in JS): add data-tooltip="Label" to the element. Markup (.tooltip-wrap + .tooltip): when you need a specific type or size (start, end, left, right, Large, Body), or a tooltip that is part of the page markup.
3. Name the controlGive the button an aria-label with the same text as the tooltip. The tooltip itself is not announced.

Tooltip

Global: data-tooltip

One shared tooltip is shown for any element with data-tooltip, including elements you add later. It is a popover in the top layer, so no overflow, z-index or stacking context can clip it or hide it. It is centered on the element, aligns to the start or end of it (as shown under Layout & Appearance in Examples & Guidelines) when it would leave the viewport sideways, and flips above or below when there is no room.

Hover the buttons: the first uses data-tooltip, the second adds data-tooltip-position="bottom".

Markup: .tooltip-wrap

Classes name where the tooltip sits next to the element: tooltip--top and tooltip--bottom (automatic), --top-start, --top-end, --bottom-start, --bottom-end, --left, --right, --left-start, --right-start and --body (always manual). tooltip--lg is Large. tooltip--manual keeps a Top or Bottom tooltip fixed and centered, and tooltip--flip, tooltip--align-start and tooltip--align-end are added by tooltip.js: never write them yourself.

API

Global tooltip

SettingEffect
data-tooltip="Label"The text. Plain text only, one to three words.
data-tooltip-position="bottom"Below the element. Default is above (top). Use Bottom in toolbars (room below), Top in table rows (room above). The flip still applies.
--tooltip-safe-top on :rootHeight in px of a sticky header. Room above then counts from below the header, so a tooltip is flipped below instead of landing on it. Set it from the breakpoint where the header sticks.
--tooltip-z on :rootz-index of tooltips in markup (.tooltip-wrap), default 300. Set it below a sticky header's z-index. The global tooltip is in the top layer and does not use it.

Things to know

  • Shows on hover and on keyboard focus (:focus-visible); Esc hides it. On touch it shows on tap and hides on the next tap elsewhere.
  • Automatic alignment and the global tooltip use CSS anchor positioning. In a browser without it the tooltip is centered on the element by script and kept inside the viewport.
  • Without tooltip.js a markup tooltip stays on its declared side, and a data-tooltip shows nothing.
  • A transform, filter or contain on an ancestor makes a markup tooltip's fixed position relative to that ancestor. The global tooltip is not affected. Use tooltip--manual if you must keep a markup tooltip there.
  • Replacing an old script: delete the page's own tooltip script and CSS (.row-tooltip, a local .tooltip block), keep the data-tooltip attributes, and add data-tooltip-position="bottom" where the old one opened below.
TopicRule
Positioning contextAutomatic tooltips are position: fixed, so a container with overflow does not clip them. A transform, filter or contain on an ancestor makes fixed relative to that ancestor: use tooltip--manual there.
Own positioning scriptA page must not position a tooltip with a script of its own (for example inline left): the script and the automatic alignment would fight over the position. Use data-tooltip, or tooltip--manual if a fixed tooltip is really needed.
Browser supportAutomatic alignment uses CSS anchor positioning. Without support the tooltip stays centered, as in manual mode.
