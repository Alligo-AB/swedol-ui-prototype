Input

An input field lets the user enter free text, numbers or search terms. It can have a label, a left icon, right-hand action icons and a message that explains or validates the value.

Every example on this page is the real component. Type, click, tab and clear the value to try it. Specification: .claude/skills/eco-input/SKILL.md.

Variants

    
Three sizes on desktop (Large 48px, Small 40px, XSmall 32px) and two on mobile (Large 40px, Small 32px). Figma has a Breakpoint property: Desktop is 769px and up, Mobile is below 769px. The component switches by itself; the Breakpoint toggle forces one for preview.

    
Breakpoint
      


    
Sizes

    
Large is for standard forms, Small for compact surfaces, XSmall for dense tables and filters (desktop only: on mobile it is not available, use Small).

    


    
Icons

    
A left icon shows the type of input (the default is search). Right-hand icons are optional: clear appears only when the field has a value, a divider separates clear from the action icons. Enable only the ones the field needs.

    


    
Messages

    
The message sits below the field, in body-sm. Hint text is neutral, error and success change the color of the border and the message. The message icon is optional and up to you; an icon next to an error message helps so color is not the only signal.

    

  







  

    
States

    
All seven states from Figma, with and without icons. Hover and focus are forced on this page; in your code they come from :hover and keyboard focus. Active means the field has a value.

Right-hand icons are 20px in every size, but the component that holds them differs. A Button (eco-button, Blank, icon only, 6px padding = 32px, grey fill on hover) holds them on Desktop Large, Desktop Small and Mobile Large. An Icon Button (just the 20px icon, it turns grey on hover) holds them on Desktop XSmall and Mobile Small. Icon color is text-action-primary. Padding top and bottom comes from the fixed height. The 6px values and the 10px gap before the icons on Mobile Large are literals: there is no spacing token for them.

Behavior and accessibility

    

      
InputResult

      
        
Type a valueThe field becomes Active: black border and the clear button appears.

        
Clear buttonEmpties the field and returns focus to it. It is a real button with an aria-label.

        
TabThe blue ring shows on keyboard focus only (body.keyboard-nav, set by a small script).

        
Hover on a right iconButton: grey fill (surface-opacity-black-05). Icon Button: the icon turns text-action-primary-hover.

        
LabelAlways a label with for and id. Search fields without a visible label need an aria-label.

        
ErrorSet aria-invalid="true" and point aria-describedby at the message.

        
DisabledNot focusable. Grey fill, light border, text-disabled for text, icons and message.

      

    
Open points: Figma binds icon/disabled, which is not in tokens.json, so the disabled icon uses text-disabled (same value). Multi-line text fields are a separate component: see Text area.

Usage

    
Choose the control by what the user is entering.

    

      
The user…Use

      
        
types free text, a number or a search termInput

        
picks one value from a fixed listeco-select

        
picks one of two or three optionseco-radio

        
picks any number of optionseco-checkbox

      

    

      

        
Do

        
    
          
  • Give every field a visible label, in sentence case for values and uppercase for the label itself.
    • 
          
  • Pick the size by breakpoint: Large for standard forms, Small for compact surfaces, XSmall for dense tables.
    • 
          
  • Explain what is wrong in the message, with the error icon.
    • 
          
  • Use pre-filled or detected values where you can, in sentence case.
    • 
        

      

      

        
Don’t

        
    
          
  • Use a placeholder as the label.
    • 
          
  • Show the focus ring on mouse click, or remove it on keyboard focus.
    • 
          
  • Use color alone for error or success.
    • 
          
  • Hardcode the colors or the heights: use the tokens and the size classes.
