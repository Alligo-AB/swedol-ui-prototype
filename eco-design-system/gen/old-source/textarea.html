Text area

A text area lets the user enter text over multiple lines: comments, feedback or longer passages that need more room than a single-line input. It has a label, an optional word count, a resizer and a message that explains or validates the value.

Every example on this page is the real component. Type, click and tab to try it. Specification: .claude/skills/eco-textarea/SKILL.md.

Variants

    
There is one size. Figma defines only the Desktop version; below 769px the label and text use the smaller mobile type styles (same as the input). The component switches by itself; the Breakpoint toggle forces one for preview.

    
Breakpoint
      


    
Word count

    
The word count sits on the label row, on the right. Use it when the text has a limit (maxlength); leave it out when there is none.

    


    
Messages

    
The message sits below the field, in body-sm. Hint text is neutral; error and success change the color of the border and the message. An error message has a leading icon so color is never the only signal.

    


    
Resizing

    
The user can drag the corner handle to make the field taller (vertical only). A disabled field cannot be resized.

Behavior and accessibility

    

      
InputResult

      
        
Type a valueThe field becomes Active (black border). The word count updates; maxlength stops typing at the limit.

        
Drag the cornerThe field grows or shrinks in height only. It never goes below the 66px minimum.

        
TabThe blue ring shows on keyboard focus only (body.keyboard-nav, set by a small script).

        
LabelAlways a label with for and id. A placeholder is never the label.

        
ErrorSet aria-invalid="true" and point aria-describedby at the message.

        
DisabledNot focusable. Grey fill, light border, text-disabled for text and message, no resize.

      

    
Open points: Figma has only a Desktop version, so the mobile type values are taken from the input. Disabled uses border-primary and focus uses a text-secondary placeholder, both as in Figma and both different from the input. The resizer is the browser’s own handle, not the 8px Figma icon. Details are in the skill’s Flags.

document.addEventListener('keydown', function (e) { if (e.key === 'Tab') document.body.classList.add('keyboard-nav'); });
document.addEventListener('mousedown', function () { document.body.classList.remove('keyboard-nav'); });

// word count: one textarea + its .form-count
function bindCount(ta, count) {
  var update = function () { count.textContent = ta.value.length + '/' + ta.maxLength; };
  ta.addEventListener('input', update); update();
}

  







  

    
Usage

    
Choose the control by what the user is entering.

    

      
The user…Use

      
        
writes a comment, feedback or a longer passageText area

        
types a short value: a name, a number, a search termeco-input

        
picks one value from a fixed listeco-select

        
picks one of two or three optionseco-radio

      

    

      

        
Do

        
    
          
  • Give every field a visible label, uppercase, and sentence case for any pre-filled text.
    • 
          
  • Show the word count when there is a character limit, and set maxlength to match.
    • 
          
  • Explain what is wrong in the message, with the error icon.
    • 
          
  • Let the user resize the field vertically.
    • 
        

      

      

        
Don’t

        
    
          
  • Use a text area for a short single-line value.
    • 
          
  • Use a placeholder as the label.
    • 
          
  • Show the focus ring on mouse click, or remove it on keyboard focus.
    • 
          
  • Use color alone for error or success.
