## What this is

`eco-design-system/` is the documentation site for ECO. It replaces the older `tokens/*.html` showcase pages, which stay in place until the user asks to remove them. No site header or footer; the breadcrumb stays.

```
eco-design-system/
  eyebrow.css              one definition of the eyebrow label style (also used by the root index.html)
  docs.css                 shared styles for every doc page (only file with doc-page CSS). Imports components/css/spacing.css, so every doc page has var(--dimension-spacing-space-md / -lg) (eco-spacing); defines --ds-accent (#E94E19, the ECO DS documentation accent, not in the token package)
  subnav.js                stuck-state hairline + active-section marker for the sticky nav, smooth jump for chips and the side list
  toc.js                   split pages: builds the chip row (below 1024px) and the sticky Contents list (from 1024px) from the headings
  tokens-loader.js         ECO.watch(): load tokens.json and re-render when it changes
  overview.html            hub: entry points, summary + live illustration per page
  foundations/colors.html  reference implementation for foundation pages — copy its structure
  foundations/<name>.html  typography, spacing, elevation, motion …
  components/tooltip.html, tooltip-specifications.html, tooltip-code.html   reference implementation for component pages (three pages, see "Split component pages")
  components/checkbox*.html, input*.html …   the Form components (checkbox, input, textarea, radio, select, switch, tabs, segment-control, range, icon-picker), converted to three pages 2026-10-12: reference for the form-control playground, toggles, states matrix and card treatment
  components/button*.html, button-group*.html   the Actions components (button, button-group), converted to three pages 2026-10-13: reference for a component with variants, sizes, content options and a badge, and for the dark-surface variants

  components/menu*.html, list-item*.html, divider*.html, links-guide.html (hub) + inline-link / action-link / tile-link, each as .html / -specifications.html / -code.html   Menus, lists and dividers and Links, converted to the three pages 2026-10-13 (hub + three types for Links, like Badge and Notifications)
  components/section*.html, collapsible*.html   Layout and content (section, collapsible), converted to three pages 2026-10-14: reference for a layout block with no states (Section) and for a row with live motion (Collapsible)

```

**Page type attribute.** Every page sets `data-ds` on `<body>`: `foundation` (`<body data-ds="foundation">`) or `component` (`<body data-ds="component">`). `docs.css` uses it to scope the spacing and card rules below, so a rule for one page type never leaks into the other.

**Page top padding** (`--pt-page` on `body`): 16px xs, 32px sm, 32px md, 40px lg, 48px xl. The breadcrumb has no top padding of its own (only 16px below).

> Never name the hub `index.html`: `npx serve` (the local server) redirects `/folder/index.html` to `/folder`, which breaks every relative path on the page.

## Principles

1. **Live, not copied.** Every swatch/specimen is rendered with `var(--…)` from the `alligo-design-tokens` CDN, never a hardcoded value. Lists of tokens are built from `.claude/skills/eco-tokens/tokens.json` by a small script on the page, using `ECO.watch(url, onData)` from `eco-design-system/tokens-loader.js`: it loads the file, then re-renders the page by itself (no reload) whenever the file changes (polled every 4 s). The render function must clear and rebuild its containers on each call. Counts in the hub are computed from the JSON too, never typed. Do not paste token values into the HTML by hand.
2. **Show drift, don't hide it.** When `tokens.json` and the live package disagree (renamed, changed or missing token), flag it on the swatch and count it in the coverage line. Never hand-edit `tokens.json` (generated by `generate-tokens.py`).
3. **Complete or declared.** The page must show every token/variant/state of its subject and say how many. Anything not placed in a group appears in an automatic "Other" section.
4. **Teach, don't just list.** Each section explains *when* to use the thing, in one or two sentences of plain English, before the examples. End every page with **Usage** (Do / Don't).
5. **ECO values only.** Type, spacing, colors and sections follow `eco-typography`, `eco-spacing`, `eco-colors`, `eco-section`. Nothing decorative that is not in the system (no rounded corners, gradients or extra fonts). Illustrations are built from tokens.

## Page anatomy (in this order)

| # | Block | Classes | Notes |
|---|---|---|---|
| 1 | Breadcrumb | `.breadcrumb` | `Home / ECO Design System / Foundations or Components / Page`. Copy from `colors.html`. |
| 2 | Intro section | `.ds-section.ds-section--first` | `.ds-eyebrow` (category), `.ds-title` (display-lg, uppercase), 1–2 `.ds-lead` (what it is and why). |
| 2b | Sticky on-page nav | `nav.ds-subnav > ul.ds-toc` | Directly after the intro section, never inside it (a sticky element only sticks inside its parent). It looks like a chip row in the intro until it reaches the top of the browser, then stays there; `docs.css` takes the nav's 12px padding out of the gaps around it so the initial spacing is unchanged. Chips link to section `id`s; `subnav.js` adds `.is-stuck` (hairline) and marks the section in view with `aria-current`. When the window is too narrow the row swipes sideways: native touch/trackpad scroll, mouse drag, and edge fades that show more chips are hidden (all done by `subnav.js` + `docs.css`; no extra markup). Clicking a chip scrolls to the section with `eco-motion` easing (`decelerate-emphasized`) and a duration by distance (fast-4 / medium-2 / slow-1 / slow-4), updates the hash, moves focus to the section, and jumps instantly under `prefers-reduced-motion`. |
| 3 | Content sections | `.ds-section` alternating with `.ds-section--secondary` | Each: `.ds-h2`, `.ds-desc` (when to use), then the specimens. Give each an `id` for the toc. |
| 4 | Usage | `.ds-rules` | `.ds-rule--do` and `.ds-rule--dont`, 3–4 short bullets each. Last section. |

Section backgrounds alternate white / grey (`eco-section`). The first section follows the breadcrumb directly.

## Spacing and card treatment

All values are mobile-first; the larger value applies from 769px (`md`).

| Between | Mobile | Desktop |
|---|---|---|
| `.ds-desc` and the block it introduces (`.ds-stage`, `.ds-table-wrap`, `.ds-playground`, `.ds-layers`, `.ds-ramp`, `.ds-grid`, `.ds-status`) | 12px | 16px |
| Block (or note under it) and the next `.ds-h3` | 32px | 48px |
| `.ds-h3` and the `.ds-desc` after it | 8px | 8px |
| Foundation pages (`data-ds="foundation"`): block and next `.ds-h3` | 56px | 56px |
| `.ds-h3` straight after a `.ds-desc` (section intro) | 0 | 0 |
| Block and the explanatory note under it: `<p class="ds-desc ds-note">` (body-md: 16/22 mobile, 17/24 desktop) | 8px | 8px |

**Cards on component pages** (`data-ds="component"`): `.ds-stage`, `.ds-controls`, `.ds-code`, `.ds-rule` have no 1px frame and use `var(--shadow-elevation-b-20)`, the same elevation as the dashboard stat cards. `.ds-controls` has 24px side padding; `.ds-code__bar` is 56px high with 24px side padding; the Do / Don't cards keep their 4px color bar on top. Tables (`.ds-table-wrap`) get the same treatment on every page type: see `eco-table`.

## Foundation pages

- Group tokens by **role**, not by file order (colors: neutrals, brand, text, border, status, state, overlays).
- Show the token name, the `var(--…)` (click to copy), hex/rgb, and the description from `tokens.json`.
- Show objective info that teaches: contrast badge for text colors, a ramp for ordered scales, matched sets for status.
- Colors page is the reference implementation: `foundations/colors.html`.
- Status matrix: build the text-token name as `text-<status>-default` for all four statuses (information, success, warning, danger). Concept-brand accents that are only primitives in the package (Tools: `--color-primitive-color-brand-tools-accent-*`) are read live from the package CSS and labelled as primitives, since `tokens.json` has semantic tokens only.

## Component pages

**Every component page is three pages** (`<name>.html`, `<name>-specifications.html`, `<name>-code.html`, see "Split component pages" below). Reference implementation: `components/tooltip.html` + `tooltip-specifications.html` + `tooltip-code.html`. **New page:** copy those three. **User asks to update or rebuild an existing one-page component page:** convert it to the three pages ("Moving a page" below); do not ask first, say what you moved. Keep the specification in the component's `eco-*` skill (link to it in the intro). The Form components (below) are the reference for form controls: playground, toggles, states matrix and card treatment.

**Form components are converted (2026-10-12):** `checkbox`, `input`, `textarea`, `radio`, `select`, `switch`, `tabs`, `segment-control`, `range` and `icon-picker`, each as the three pages. They share the playground, the toggles, the card treatment and the spacing, so every Form page looks and behaves the same; copy the nearest one (checkbox for a control with Mode, inline menu and tiles, input for fields with sizes and a Breakpoint, switch for light and dark, radio for a group). Only the toggles and variants that the component really has change (no Mode toggle without a dark mode). How they differ from the one-page template:
- **Sections.** The 11 Examples sections, with extra ones after the closest standard one (checkbox: **Tiles** after Variants; segment control: **Motion** after Playground). A component that has no variants or sizes skips them and says so (Icon picker has no Variants, no Sizes; Range has a short Sizes). The old "Anatomy & specs" is split: the numbered **Anatomy** goes on Examples, **Sizes**, **Measurements**, **Design Tokens** and **States** on Specifications.
- **Playground and Variants controls** are the shared components (`btn-group`, `eco-select`, `eco-input`, `eco-range`). Mode is `data-mode-toggle` + `DK.mode(fn)` (the Playground stage is not a `data-mode-stage`: it has its own Mode field). Breakpoint is `data-bp-toggle data-bp-force` + `DK.bp(fn)`; no `body[data-bp]` overrides are left. Size toggles that lose an option on mobile (Input and Select XSmall) are disabled in the `DK.bp` callback.
- **Spec tables are built live** (`DK.tokenTable`, `DK.recipes`, `DK.printCss`); the component's own builder (`cb()`, `field()`, `radio()`, `sw()` …) is copied, not rewritten, so the Playground, the Variants and the States matrix share one markup.
- **Measurements:** padding comes from the real subject. For a control whose space is a **margin** (checkbox, radio) put `data-measure-margin` on the subject (`components/js/measure.js` then reads the margin of the input), with `style="--k:4"` on the `.measure` so a 24px control is readable. A control with no padding or margin (switch, range) has the table only, with a note, like Badge Dot. A tab, a pill segment control, a select and an input measure their real padding; their figure has the Breakpoint toolbar.
- **Anatomy** uses `DK.callouts` on the real component. Where the part is text, pass `box: function () { var r = document.createRange(); r.selectNodeContents(el); return r.getBoundingClientRect(); }` (a `.form-label` is a block, so its own box is the whole row). An element that only exists while it is open (the icon picker panel) is drawn as a static copy built from the component's own classes, `inert`, with a caption saying so.
- **Motion** on a component that animates: a table under Specifications → Motion; the live easing and duration section (`DK.motion`) stays on Examples after Playground (segment control). After the call, remove `ds-section--secondary` from every section and put a `<div class="ds-sep"><hr class="divider" /></div>` before `#motion`: `DK.motion` flips backgrounds for the old alternating layout.
- **Not verified with Figma** (`badge-basic--warning badge-basic--weak` in `.ds-eyebrow-row`) stays on segment control, range and icon picker, on all three pages.
- **Stylesheet order.** `textarea.css` repeats `.form-label` without `.form-label--sm`, so it is linked **before** `input.css` (the docs controls use `form-label--sm`); every other component file after the base files.
- **Grids** in demos use `grid-template-columns: minmax(0, 1fr)`, never `1fr`: an input has an intrinsic width and `1fr` then overflows at 375px.

**Actions components are converted (2026-10-13):** `button` and `button-group`, each as the three pages (`gen_button.py`, `gen_button_group.py`). Same frame, playground, card treatment and spacing as the Form pages; what is specific to them:
- **Button** has 12 Examples sections: the standard 11 plus **Icon buttons** (toggle icons and Close) after Variants. Variants holds the ds-groups Hierarchy, Which variant, With icons, Badge and System buttons and selected; **Combinations** (pairs of buttons) is Layout & Appearance → Alignment. The Usage Do / Don't pairs are all the component itself (one Primary vs two, a short label vs a sentence, an inverted variant vs a normal one on a dark surface).
- **Dark surface, no Mode toggle.** The inverted variants only exist on a dark surface, so there is no Mode field: the Hierarchy figure has a second `ds-fig__stage ds-stage--dark`, and the Playground stage gets `ds-stage--dark` itself when an inverted variant is chosen. A Do / Don't pair about the surface has both stages dark (`pair_cls(..., 'ds-stage--dark')` in `gen_button.py`).
- **Playground groups that do not fit** the 272px controls column are swapped for an `eco-select` with the same options (the script is kept in `button.html`; `eco-button`, Button group, describes the rule). This is why Size, State and Breakpoint show as selects at ~1280px. The group stays visible when it fits.
- **Specifications → States** has three ds-groups: the variant × state matrix (with the Size toggle), the toggle-icon matrix (Size toggle) and the Close matrix. **Sizes** holds the size table, the badge-size table (both built from the `SIZES` numbers in the page script) and the icon-button boxes. **Measurements** shows the padding of a Secondary button per size at `--k:2` with the Breakpoint toolbar; the label inset is in the table, not the figure.
- **Button group** has one size (Small System buttons), so its Sizes section is short, and no Figma component, so **Not verified with Figma** stays on all three pages. A group that is too wide is cut off in a figure (`.bg-fig { overflow: hidden }`), never wrapped. Measurements draw one button of a one-button group.
- **Figma descriptions (2026-10-13).** The usage guidance on the Button page comes from the descriptions on the Figma component set `2007:68126` (read with `use_figma`: `node.description` on the set and on every variant; the variants repeat the set's text per style). It feeds Overview, Variants → Which variant, the Usage Do / Don't pairs (one Primary vs several, a specific Destructive label, Accent is not for “Add to cart”, a variant with enough contrast), the Behavior groups (System selected, Destructive actions) and the Accessibility label rule. **Inverted variants are chosen by context, visibility and contrast, not by background color alone, and are not limited to dark surfaces**: the docs page still previews them on a dark stage, but never says they are dark-only. Re-read the descriptions when Figma changes and update `gen_button.py` and `eco-button` together. The Button group has no Figma description.
- **Button guidance (2026-10-13).** The Button page also carries the guidance on the page: the "When to use each variant" table has three columns (Variant, Use when, Avoid when); **Combining variants** (Variants, with the pair figure `#v-pairs`); **Icon only** (Variants, Behavior); **Writing button labels** (Usage, with the long-label and vague-label Do / Don't pairs). **Anatomy** has two figures: the button with an icon, a label and a number badge, and an icon-only button with a dot. Two Do figures are live in Combining variants: a Secondary pair above a System pair with trailing icons (`select_all`, `deselect`), and the real **E-Com Toast** card (`ecom-toast--cart`, from `notifications.css`, linked on that page only through `head_extra` in `gen_button.py` / `build.py`, **before** `button.css`: `notifications.css` has its own `.btn` base and would shrink every button to 32px if it came after) with Blank and Primary buttons, as in `eco-toast-ecom`. Placement of the Primary button, stacking and truncation are **Layout** rules and are not on the Button page: Layout & Appearance → Alignment is a "To be added to the Foundations (Layout) page" note. When that page exists, link it from there.
- **Open points** are listed on the pages, not fixed: `ss02`/`ss03` missing on Small; the 6px literals.

**Notifications are converted (2026-10-13):** the hub `notifications.html` and the five types `toast`, `toast-ecom`, `modal`, `banner`, `inline`, each as the three pages (`gen_notifications.py`, `gen_toast.py`, `gen_toast_ecom.py`, `gen_modal.py`, `gen_banner.py`, `gen_inline.py`, shared helpers in `gen/notif.py`). A family with several types, so it follows the Badge pattern: the hub is one page with no tab bar (chooser, decision matrix, status and icon, emphasis guide, dismissing, in action, usage), the type pages are its `children` in `docnav.js`, the breadcrumb is `Components / Notifications / Toast` (`parent` in the generator dict) and each set has only its own three tabs. Same frame, playground, card treatment and spacing as the Form and Actions pages; what is specific to them:
- **Stylesheet order (`pre_css`).** `notifications.css` has its own `.btn` and `.inline-link` base, so it is linked **before** `docs.css` (key `pre_css` in the generator, Examples and Specifications pages): `docs.css` imports `button.css` and `inline-link.css`, which then win for every docs button and link. A bare `.btn` in a notification demo would then be Large, so `notifications.css` has a scoped rule, `:is(.toast, .ecom-toast, .modal, .banner-notification, .inline-notification) .btn`, that keeps every button inside a notification 32px high (XSmall from 769px, Small below) whatever else is on the page. Playground triggers and scenario buttons are docs controls: `btn btn--primary btn--sm` (and the Motion "Show again" button, `btn btn--secondary btn--sm` in `doc-kit.js`).

**How to build it**
- **One builder function** creates every example (`cb({dark, small, menu, checked, mixed, disabled, state, label, aria})`-style) so playground, variants and matrix always use the same markup.
- **Component CSS lives in `components/css/<name>.css`** (repo root, shared with prototypes and products), linked from the page with `<link rel="stylesheet" href="../../components/css/<name>.css">`. Not in `docs.css`, not in a `<style id>` block in the page: it is the component, and the Code section fetches and prints the same file (use `DK.printCss(pre, name, strip)` from `doc-kit.js`; a component with two files, like Select, fetches both). Behaviour JS the same way in `components/js/`. Force hover/focus for the matrix with `:is(:hover, [data-state="hover"])` pairs; the Code section strips the `[data-state]` half before printing (`replace`).
- **Mode, Breakpoint and other global toggles** are `[data-…-toggle]` groups that all stay in sync (`aria-pressed`); the choice applies via a class on the stages or a `data-bp` attribute on `<body>`. A Breakpoint toggle (Window / Desktop / Mobile) only previews what the component does by itself at 769px: it forces the values with page-local CSS and is never part of the component CSS.
- **Mobile**: mobile styling below 769px (`sm` looks like mobile), the Breakpoint axis in Figma = Desktop (769px+) / Mobile (below 769px).
- Page-local CSS is only layout (rows, columns, group spacing) and the state-forcing for the demo; no component or token values.

## Split component pages: Examples & Guidelines / Specifications / Code

**Adopted (2026-10-12).** Component pages are **three pages**: `components/tooltip.html`, `tooltip-specifications.html`, `tooltip-code.html` are the reference implementation. New component pages are built this way; an existing one-page component page is converted to it when the user asks to update or rebuild it. Foundation pages (colors, typography, spacing …) stay single pages. **A component with several types** (Badge: Basic, Dot, Number, Product & Discount, Purchase Info) gets a **hub page** `<name>.html` (one page: Overview, Usage, Color, Emphasis, with a table of the types) and one three-page set per type, `<name>-<type>.html`, `-specifications.html`, `-code.html`, with the type pages as `children` of the hub in `docnav.js` (the Links guide pattern) and the breadcrumb `Components / Badge / Dot`. The hub has no tab bar, and it must not get tabs to the type pages (decided 2026-10-12: the side menu and the table of types on the hub are the way to the type pages); each type page set has only its own three tabs (`aria-label="Badge Dot"`). The old one-page Tooltip pages are deleted.

| Page | File | Holds |
|---|---|---|
| **Examples & Guidelines** | `<name>.html` (the overview card links here) | The 11 sections below |
| **Specifications** | `<name>-specifications.html` | Technical values |
| **Code** | `<name>-code.html` | How to use it in code |

**Page frame.** Breadcrumb (on the sub pages `Tooltip` is a link and the page name is the current item), intro (`.ds-section--first`), then `<div class="ds-tabs"><nav class="tab-bar tab-bar--primary" aria-label="<Component>">` with three `<a class="tab">` (eco-tabs link tabs, `aria-current="page"` on the current one; the same `aria-label` on all three pages so the line slides across the page load). Link `/components/css/tabs.css` and put `/components/js/tabs.js` in `<head>`. Then `<div class="ds-doc">` holds all sections, and the page ends with `toc.js` **before** `subnav.js`. The tab bar's design is the eco-tabs default and may change later.

**Contents navigation (built by `toc.js`, no markup to write).** Level 1 = each `section.ds-section[id]` (its `.ds-h2`), level 2 = each `.ds-h3.ds-group` inside it (given an id when it has none). A plain `.ds-h3` is not listed (a third level is an open question). From 1024px a sticky "Contents" list sits in the right margin (`.ds-sidetoc`; the item in view is marked with `aria-current`, the list scrolls by itself if it is taller than the window) and the sections get `padding-right: calc(var(--toc-w) + var(--toc-gap))` (list 192px + 40px gap, `docs.css`). From 1024px the whole block (1200px text + gap + list) is centred beside the navigation, so both side margins are equal (`--px-full` is set from that block in `docs.css`, for pages with `.ds-doc`). Below 1024px the existing chip row (`.ds-subnav`, sections only) is built instead. So in the content: **section title = `.ds-h2`, sub-heading that belongs in the list = `h3.ds-h3.ds-group`, anything smaller = `h3.ds-h3`**. Sections alternate white / `ds-section--secondary` (the split pages are all white with dividers, see the layout below). Do not add `DK.motion` or `DK.callouts` expecting a hand-written subnav chip: pages with `.ds-doc` do not have one.

**Heading anchors (built by `toc.js`, no markup to write).** Every heading in the Contents list (`.ds-h2` and `h3.ds-group`) gets a Blank icon button (`icon-btn ds-anchor`, the Material Symbols `link` glyph, `aria-label` "Copy link to <heading>", `data-tooltip` "Copy link to heading") appended to it. A click copies the URL of that heading (`location.origin + pathname + #id`), sets the hash with `history.replaceState` (no scroll), and shows the ECO success **system toast** "URL to heading copied" (4 s, **Weak**: a routine confirmation is the quiet tier, see `notifications-guide` → "Choosing the emphasis"; the error toast is Weak too). If the browser refuses to copy, an error toast says to copy the URL from the address bar. The toast needs `notifications.css` and `notifications.js`: they are **loaded on the first click** (the stylesheet is inserted before `docs.css`, so docs and component files win over its own `.btn` base). From 1024px the icon hangs in the left margin (`left: -32px`) and shows on heading hover or keyboard focus (the heading's `::before` extends the hover area over the margin); below 1024px it follows the heading text; on touch screens (`hover: none`) it is always visible. Styles `.ds-anchor` in `docs.css` (with `.ds-doc` in the selector, so they beat `button.css`). A plain `h3.ds-h3` is not in the Contents list and has no anchor. **Publishing:** copying needs `navigator.clipboard`, which only works over **HTTPS** (or `localhost`); over plain `http://` the code falls back to `document.execCommand('copy')`, an old API that browsers may remove. Inside an `<iframe>` the host page must allow it (`allow="clipboard-write"`), otherwise the user gets the error toast. The success path has only been verified by reading the code: the preview browser denies the clipboard, so test one real click on the published site.

**Layout of the split pages (shared rules in `docs.css`; only the demo layout of one page stays page-local, e.g. the Tooltip variants grid).** Used as written for every component page.

**Breakpoint control in the Playground.** A component whose values change at 769px gets a *Breakpoint* field (Window / Desktop / Mobile) in its Playground controls: `<div class="btn-group" data-bp-toggle data-bp-force>` and `DK.bp()` in the page script. `data-bp-force` makes `doc-kit.js` switch the `@media (min-width: 769px)` and `(max-width: 768px)` rules of the stylesheets in `components/css/` to "all" or "not all", so the real component CSS shows the Mobile or Desktop values whatever the window width (docs.css is never touched, so the docs layout follows the window). **Measurements** (Specifications, replaces the old Spacing section; the name follows Material, "Dimensions" alone would leave out padding). `h2` Measurements with two groups: **Dimensions** (a measurement figure plus an *Attribute / Value* table: padding per side, line height, height, max width, corners) and **Spacing** (the same padding and distances as spacing tokens, plain `h3` Padding / Beak and distance). The figure is the shared blueprint figure `components/css/measure.css` + `components/js/measure.js`: the real component at true size, 1:1 (`--k: 1`; set `style="--k:2"` on one `.measure` only when a component is too small to read) on a dotted grid, padding shaded with `surface-information-weak` (overlaps get deeper), dimension lines in `border-information-default`, numbers in `text-information-default` (blue = blueprint; tokens only). The script reads the padding from the real `.measure__subject`, so the numbers are live. A subject with a status edge outside its padding (toast, banner, inline) marks the edge `data-measure-edge` (on the subject itself it means its left border; on another element, that element's width): `measure.js` sets `--edge` and the left shading and the left dimension start after it. **Breakpoints:** when the component's padding changes at 769px (most components do), the figure has a *Breakpoint* toolbar (Window / Desktop / Mobile, `data-bp-toggle data-bp-force`, built in by the `measure_fig` helper of the generator, see the Playground control) and the page script calls `DK.bp(function () { ECO_MEASURE.init(); })`, so the figure re-measures the real component under the forced breakpoint (it also re-measures on window resize). A side with no padding is hidden. The table under the figure always lists both breakpoints. Leave the toolbar out when the values are the same everywhere (Tooltip). Markup per size: `.measure__item > .measure__name + .measure__obj` holding the subject (inside its own wrapper, e.g. `.tooltip-wrap`, so the component's variables apply), four `<i class="measure__pad measure__pad--t|b|l|r">` and four `<b class="measure__dim measure__dim--v|h measure__dim--t|b|l|r"><span></span></b>`; put the `.measure` in a `.ds-fig__stage` with `padding:0;min-height:0`. One item per size (Small, Large, …); a component with a fixed target size (checkbox: container 18, target 48, state layer 40) shows those as extra lines in the table. A component with no padding to draw (a divider) skips the figure and keeps the table.

## Back to top

## Motion section

When a component animates (close, open, enter, exit), give the page its own **Motion** section right after the playground, so the reader can compare easing and duration live. Use `DK.motion({ anchor, prefix, rec, why, collapse, preview })` from `eco-design-system/doc-kit.js` (Banner and Inline notification are the reference; `collapsible.html` and `segment-control.html` use `always: true` for previews with no close button). It builds the section (preview stage + controls, same layout as the playground), adds a "Motion" chip to the subnav and flips the background of the later sections so they keep alternating.

- Controls (sliders are the shared `eco-range` component: the page must link `/components/css/range.css` and `/components/js/range.js`): slider **Easing** (all four eco-motion easings), slider **Duration** (all 12 duration tokens, fast-1 … slow-4, tick labels in ms), **toggle button group** "Height" (Fade only / Collapse, `.ds-seg`; only with `collapse`) and Show again.
- `role: 'exit'` (component closes or is removed) adds a live warning under the controls and a table "Recommendations and warnings": Decelerate easing (made for enter, use Accelerate), Slow duration 450 ms or more (a closing element should leave quickly), Height Fade only (content jumps up). Other roles (enter, hover) need their own rules in `WARN` in `doc-kit.js` before use.
- Table "Motion for this selection": Property / Token / Value / Recommended, read live from the tokens.
- The component CSS reads `--<prefix>-ease` / `--<prefix>-duration` with the **recommended value as fallback**, and the JS skips the collapse inside `[data-<prefix>="fade"]`.
- `rec` = the recommended default for that component from `eco-motion` (combination rule: distance + fade + easing); `why` = one sentence. Recommended is marked `*`.
- Two motions on one page (Toast: enter + exit): pass `parts: [{ title, prefix, rec, exit }]` instead of `prefix`/`rec` (one Easing + Duration slider pair per part, `exit: true` gets the exit warnings) and `show()` instead of `preview()` for a component that is fixed in the window: the vars are set on `<html>` and the stage shows a hint plus a Show toast button. Reference: `components/toast.html`, `toast-ecom.html`.
- **Link to it from the playground and the code block.** `DK.motion` gives the section `id="motion"`. Add `<p class="pg-note" style="margin:0">The animation … is set in <a href="#motion" class="inline-link inline-link--small">Motion</a>.</p>` in the playground controls (before the Show/Show again button) and `<p class="ds-desc ds-note">The markup has no motion. … is set in <a href="#motion" class="inline-link inline-link--small">Motion</a>.</p>` under the code block. Reference: `banner.html`, `toast.html`, `toast-ecom.html`. No other element on the page may use `id="motion"` (name a spec table body `motion-rows`).
- When asked to build a component page for something that animates, **suggest** adding the Motion section (and the recommended default) before building it.


## Text fields in a playground

Playground text fields are the shared **`eco-input`**, never a docs-only style: `<div class="ds-field form-field"><label class="form-label" for="id">Label</label><div class="input-wrap"><div class="input-box"><input class="form-input" type="text" id="id" value="…" placeholder="Label" /></div></div></div>`, and the page links `/components/css/input.css`. ## Controls in a playground are the real components

Every control in a playground or toolbar is the shared component, never a docs-only style: option groups = the **button group** (`.btn-group`, joined System buttons, 2–4 options; link `/components/css/button-group.css`; see `eco-button`). The pill `eco-pill-segment-control` is not used in docs playgrounds, dropdowns = **`eco-select`** (`.form-select.form-select--sm` inside `.input-wrap`, plus `select.css`, `menu.css`, `select-menu.js`), text fields = **`eco-input`** (`.input-box--sm`), sliders = **`eco-range`**, single toggle buttons = **`eco-button`** (`btn btn--system btn--sm`). Field labels use `form-label form-label--sm`. Use the Small size. `docs.css` has no rules for these controls; fix the shared file instead.
