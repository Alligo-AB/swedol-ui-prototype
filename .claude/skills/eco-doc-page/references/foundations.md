## Foundation pages

- Group tokens by **role**, not by file order (colors: neutrals, brand, text, border, status, state, overlays).
- Show the token name, the `var(--…)` (click to copy), hex/rgb, and the description from `tokens.json`.
- Show objective info that teaches: contrast badge for text colors, a ramp for ordered scales, matched sets for status.
- Colors is the reference implementation: `foundations/colors*.html` (three pages, see "Foundations in the new structure"). Layout is the second (Grid / Breakpoints / Spacing / Tokens). The other foundations (typography, elevation, motion) are still the old single pages until they are migrated.
- Color card body (2026-10-22), labelled rows in this order: **Design token** (`var(--…)` + copy), **Hex code**, **RGB Value**, **Purpose** and **Suitable for**: `COLORKIT.splitDesc()` splits the one `tokens.json` description at the first sentence that starts with "Suitable" or "Use"/"Used" (that sentence is Suitable for, the rest is Purpose, the "Purpose:" prefix is dropped; "-" when a part is empty; 2026-10-22). Descriptions with no such sentence (for example "Reserved for … use only when …") show "-" in Suitable for. Classes `ds-swatch__row/label/val`. The row text (label, value, token) is body-md, 16/22 → 17/24 from 769px (changed from body-sm 2026-10-22; the swatch name stays 16/22).
- Cards / Table switch (2026-10-22): **the Text and Icon tables have a Contrast column** (ratio and grade on the intended surface, as the card badge; icons graded AA at 3:1; host `_tcols = COLORKIT.SEMANTIC_CONTRAST`, cards unchanged); **the default view is Table** (`DEFAULT_VIEW` in `color-kit.js`, 2026-10-22; where the column is too narrow for the table, CSS shows cards anyway). a Pill Segment Control (`--sm`) next to each section's h2 sets that section as cards or as a table; a page-level one under the intro sets all sections. `add()` in `colors.html` records every token for both views; the table (`.ds-ctable` + `.ds-table`) is built next to each grid and shown by `data-view="table"` on the section (CSS only). The table view exists only when the text column is wide enough (changed 2026-10-22 when the page got the Contents list, which takes 232px: at 1024px the column is only ~480px): `color-kit.js` `fit()` sets `html.ck-wide` when the column is at least 880px (from about 1300px on a page with a Contents list; at ~1600–1700px with the pinned panel it is off again), otherwise the sections always show cards and both switches are hidden (`:root:not(.ck-wide)` in `docs.css`; the chosen view is kept and returns). The table text is body-md (16/22, 17/24 from 769px; changed from body-sm 2026-10-22, the token and copy text inherit it; rows have 20px top padding so the first 24px line centers on the 40px swatch, header cells 16px top and bottom). The table header is sticky at the top of the window (`:root { --ds-subnav-h: 0px }` page-local: no sticky bar above the table where it exists; the wrap has `overflow: visible`, since a scroll container stops `position: sticky`; header line is an inset shadow). Controls added after page load need `ECO_SEGMENT.init(container)`. Whether other foundations get the same switch is open.
- Status matrix: build the text-token name as `text-<status>-default` for all four statuses (information, success, warning, danger). Concept-brand accents that are only primitives in the package (Tools: `--color-primitive-color-brand-tools-accent-*`) are read live from the package CSS and labelled as primitives, since `tokens.json` has semantic tokens only.


## Foundations in the new structure (Colors, 2026-10-22)

A Foundation uses the same frame as a component (primary tab bar, `.ds-doc data-subnav="tabs"`, Contents list, docnav, footer, all-white sections with `.ds-sep`) but **not** the fixed Examples / Specifications / Code tabs: the tabs are the ones that fit the topic, and a foundation may be one page (decide per foundation, ask when unsure). **Colors has three**: **Overview** (`colors.html`: what semantic and primitive colors are, how a token is derived (hex → primitive → semantic → component, a live diagram), token families table, Online vs traditional, Contrast ratios with the WCAG table, Usage Do / Don't, References), **Primitive colors** (`colors-primitives.html`: Neutral, System, Concept brand colors, Text emphasis, Opacity) and **Semantic tokens** (`colors-tokens.html`: the old page's sections Neutrals, Brand accent, Text & icon, Border, Status, Action & state, Overlays, with the Cards / Table switch). Text from the Supernova pages is placed where it fits, wording edited; the card and table design and content are unchanged.
- **Generator.** `gen/gen_colors.py` uses the custom page set of `build.py` (`pages=[dict(kind, suffix, label, lead, secs, js)]`, like the Hero banner widget) plus three keys added 2026-10-22: `out` (folder, here `foundations/`), `crumb_group` (`(href, title)`, here Foundations) and `first_plain` (the first page has the plain title, not `: Storyblok widget`). `body_js` loads `../tokens-loader.js`, `../color-kit.js` and `pill-segment-control.js`; the page-local style is `STYLE`. The pages are hand-editable like any component page; the old one-page version is `gen/old-source/colors.html`. `docnav.js` strips `-primitives` and `-tokens` from the page name, so all three tabs are the one item **Colors** in the Foundations group. `data-ds="component"` is kept (card treatment, spacing) on these pages.
- **Primitives are read live from the package file** (`alligo-design-tokens/dist/css/base/color.css`, fetched with CORS; they are not in `tokens.json`): `COLORKIT.fetchPackage()` returns every `--color-primitive-color-*` and, for each, the semantic tokens that point at it directly (`Used by`). Groups are by name (`neutral-`, `system-`, `brand-`, `text-`, `opacity-`) with the order of the old Supernova page; anything unplaced lands in an automatic **Other** section; the Coverage section counts them. Grolls and Univern primitives exist in the package but are left out on purpose (removed at the user's request 2026-10-22: `SKIP` in the page script); the Coverage line says how many are not documented. A swatch card has the rows Design token, Hex code, RGB Value and Used by (semantic cards: Purpose and Suitable for).
- **Card and table are one definition** (`COLORKIT.COLS`, row lists `SEMANTIC` and `PRIMITIVE`): add a column once and both views get it. `COLORKIT.add(host, rec)` records a token for the card and the table view, `finish()` builds the tables, the per-section switches and the page switch.
- **Online vs traditional** figures and the token diagram use tokens only (`var(--color-surface-NN)`, the Swedol and Tools accents); the hex in the diagram is read from the package. Supernova's contrast text said 7:1 for normal text at "AA"; the page states the real WCAG values (AA 4.5:1 / 3:1, AAA 7:1 / 4.5:1), matching the badges on the swatches.
- Heads-up for the next foundation: the Contents list is built when the page loads, so a section created later by script (the "Other" sections) is not in it.

### Layout (2026-10-22)

`foundations/layout.html` (**Grid**), `layout-breakpoints.html`, `layout-spacing.html` and `layout-tokens.html`, built by `gen/gen_layout.py` (same custom page set as Colors). Structure and text from the Supernova pages (Grid, Breakpoints, Spacing, Token) and the Figma frames `3991:161037` (Breakpoint Values) and `3991:163229` (Responsive Layout); the design is ECO's. `docnav.js` shows one item **Layout** in the Foundations group (replacing Spacing; `-breakpoints` and `-spacing` are stripped like `-tokens`), and both overview pages have a Layout card (Spacing card removed; meta line is computed from `tokens.json`).
- **Grid** (Overview · Anatomy · Grid by breakpoint · Try the grid · Build with the grid · Usage · References): anatomy with `DK.callouts` on the real parts of a scaled grid figure; one figure per breakpoint; a playground (window width select + Full / Halves / Quarters) that prints the `col-span-*` classes; code boxes (Tailwind and CSS) built from the live values. Supernova said the Small grid is "4-column"; it is 8 (fixed on the page).
- **Breakpoints**: a live ruler showing the breakpoint of the window (`resize`), the table (margin, gutter and columns read from the package), "Small is mobile" (Desktop base styling starts at 769px), what changes at Desktop, Usage (min-width queries and Tailwind `screens`, printed from `LAYOUT.BPS`), how to check a breakpoint.
- **Spacing** is the old Spacing page moved in unchanged in content (scale, layout spacing `space-md` / `space-lg`, consumer classes, directional reference, code); its script is sliced from `old-source/spacing.html` by `old_js()`. The `.sp-*` classes stay in `docs.css`.
- **Tokens**: every layout token of the package file `dist/css/base/dimension.css` (breakpoint, margin, gutter, column, section padding, layout whitespace), fetched as text so the description comment of each token is shown; the value is resolved live and the reference chain ("Points at") is parsed. Open points of the package are listed on the page: `bp-*` hold range ends, columns exist twice (a number and a px value), the tokens with no breakpoint in the name hold the Large value, `space-md` / `space-lg` are not in the package.
- **`layout-kit.js`** (global `LAYOUT`): `BPS` (id, name, token, from, to, device, base, example width, token names), `resolve(var)` (a token that points at another becomes a number: a probe element reads the computed width; a unitless token is read directly), `vals(bp)`, `bpFor(width)`, `gridFig(bp, { h, itemH, items })`, `fit()` (scales every `.lg-fig` to its container; the frame is drawn at the real breakpoint width, 375 to 1440px), `fetchDoc()`. A figure sits in a flex stage, so `docs.css` gives the host `width: 100%; min-width: 0` (`:has(> .lg-fig)`), or the host grows to the frame width and nothing scales. Colors of the figure: margin `surface-15`, column `surface-information-weaker`, frame `surface-raised-primary`.
- **XLarge:** the margin is "infinite" (the content area stops at 1200px, `--max-w`); the figure shows the 1440px Figma prototype, where `site-margin-xl` (120px) is what is left on each side.
- Heads-up: `DK.bp` (the Breakpoint toolbar) is not used here; it forces component CSS, while these pages show the grid values themselves.
