## Header art: figure + technical drawing (optional, Switch is the reference, 2026-10-18)

A component page may carry art on the right of the header: the Hairline figure (`.claude/skills/eco-card-animation`) on the left half fading into a blueprint drawing (thin lines, grid, dimensions, spacing marks, token callouts, a CSS snippet) on the right half. Files: `eco-design-system/doc-hero.css`, `eco-design-system/gen/hero_switch.py` (prints the drawing SVG; copy and change geometry, dimensions and callouts for another component) and, on the page, `../../hairline/hairline-card.css`, `../../hairline/kernel.js`, `../../hairline/embed.js`.
- Markup in the header `.ds-inner`: `<div class="ds-hero-split"><div class="ds-hero-split__text">…eyebrow, h1, leads…</div><div class="ds-hero-art" aria-hidden="true"><div data-hairline-card="<name>" data-src="../../hairline/<name>.js"></div><svg class="ds-hero-art__bp">…</svg></div></div>`.
- Shown from 1360px only (hidden below, no mobile version); the art bleeds right into the Contents column; the text column keeps ≥440px. The figure's mask is relative to its 5:4 stage (≈63% of the art's width), the drawing's mask to the whole art.
- The drawing is decorative (`aria-hidden`, `pointer-events: none`): lines and labels use tokens (`--color-text-tertiary`, `--color-surface-success-default`), labels in Breuer Condensed, only the CSS snippet is monospace. Drawing numbers come from the component spec (1 px = 5 units).
- Verified at 390, 1100, 1359, 1360, 1440, 1600, 1920 (no horizontal scroll). The page needs a server (`npx serve .`), because the figure is fetched.
- **Three layouts tried (2026-10-18), compare them in `components/switch-header-versions.html`** (a copy of switch.html with the header three times; rebuild with `python3 eco-design-system/gen/build_switch_header_versions.py`): **v1** flat drawing beside the figure (what `switch.html` has, `gen/hero_switch.py`); **v2** isometric drawing in the figure's own camera lying over it and taking over where the figure fades (`.ds-hero-art--iso`, `gen/hero_switch_iso.py`, projection constants copied from `hairline/switch.js` camera + fit, update them if those change); **v3** the flat drawing as a faint background element behind the header, the figure in front unmasked (`.ds-hero-split--bg` + `.ds-hero-bg`). The user picks one; the others stay as files until told otherwise.
- **v2b (2026-10-19), the chosen direction so far:** v2 as one background scene (`.ds-hero-split--scene` > `.ds-hero-scene`, built by `python3 gen/hero_switch_iso.py scene`): the figure sits inside the drawing's own SVG as a `foreignObject` (a static picture, pointer-events none), so figure and drawing share one projection and scale (`preserveAspectRatio xMaxYMid meet`). The drawing adds only what the figure does not draw: ground grid, long axes through slots and thumbs, extension lines, registration crosses, spacing ticks, dimensions and token callouts. It lies behind the header text and fades out on all four sides by mask (opacity .45 from 769px, full from 1360px). Below 769px it stays as a faint picture (opacity .2): 2.2 × the header width, `left: -80%`, 300px tall, clipped by the header (`overflow: hidden`), so the figure shows and the page does not scroll sideways. The scene size follows the header height (meet), so a taller header gives a bigger figure. v1, v2 and v3 stay on the comparison page until the user drops them.
- The scene's figure has `data-flat` (option in `hairline/switch.js`): the slab is only its top plane, no thickness and no reflection, and `data-part="slab"` is painted 30% opaque in `doc-hero.css`, so the grid shows through. Other uses of the figure (cards) keep the thick slab.
- **The scene's technical content represents the page's three tabs** (`gen/hero_switch_iso.py scene`, only the data blocks, taken from the real pages/spec): *Examples & Guidelines* (when to use, keys, ring, WCAG), *Code* (markup, classes, Tailwind equivalent with the 150ms easing) and *Specifications* (sizes, gap, label type, motion), plus a colour swatch list (token + hex, from `eco-tokens`) and token callouts to the figure; a dashed `border-focus` ring around the Email thumb. For another component, take each block from its own three pages, do not invent values. The scene's viewBox is taller than the figure's stage (`-24 .. 344`) to leave room above and below; the figure keeps its scale because the box is width-limited.
- Scene opacity (variables on `.ds-hero-scene`): drawing `--hs-draw` .3; figure `--hs-fig` .5 from 769px, .8 above 1300px; 640-768px the whole scene is .2 (both variables 1); below 640px (xs) the scene is off (too busy behind the text).
- **`components/switch.html` now carries v2b** (2026-10-19). v1, v2 and v3 stay on `components/switch-header-versions.html` (rebuild: `python3 eco-design-system/gen/build_switch_header_versions.py`, which reads the header text from `gen/switch_header_text.html`). Edit the live header in `switch.html`; regenerate its scene SVG with `python3 gen/hero_switch_iso.py scene`. Header text changes must also be made in `gen/switch_header_text.html` so the comparison page stays in step.
- **Button page has the same header art (2026-10-19):** `components/button.html`, scene from `python3 gen/hero_button_iso.py` (copy of the Switch generator with button-pair's geometry/camera constants and the numbers of the three Button pages), figure `hairline/button-pair.js` with the `data-flat` option. Header text copy: `gen/button_header_text.html`. **Recipe for the next component:** (1) the figure exists in `hairline/` (the same file feeds the card and the header), add the `data-flat` block to it if missing; (2) copy `gen/hero_button_iso.py`, change the camera constants (run a kernel `proj` on the figure's `Cam`/`fit` points), the geometry, the dimensions, the callouts, the swatches (`eco-tokens`) and the three tab blocks (from the component's own three pages); (3) put the scene in the page header with the markup above and link `doc-hero.css`, `hairline-card.css`, `kernel.js`, `embed.js`; (4) check 390–1920px.
- **Shared helpers (2026-10-21):** `gen/hero_scene_lib.py` (projection `make(OX,OY,SX,SY,SZ)` with SX = S·cos45, SY = .5·S·sin45, SZ = S·√.75, OX/OY from the figure's `fit`; `scene(...)` builds grid, axes, figure `foreignObject`, callouts, swatches and the three tab blocks) and `gen/apply_hero.py <page.html> <scene.svg>` (puts the scene into the first page's header, links `doc-hero.css`/`hairline-card.css`, adds `kernel.js`/`embed.js`; idempotent). A component script is then only its geometry, dimensions, callouts and tab data: `gen/hero_button_group_iso.py` is the reference. Pages stay hand-edited (the page generators do not carry the scene; regenerating a page drops it, run `apply_hero.py` again). Done: Switch, Button, Button group, Checkbox (`gen/hero_checkbox_iso.py`), Radio (`gen/hero_radio_iso.py`), Input (`gen/hero_input_iso.py`).
- Known: `button.html` scrolls sideways below ~770px because of its tab bar (not the scene).
