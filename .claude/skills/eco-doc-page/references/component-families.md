# Component families: what is specific to each

## Contents

- Form components are converted
- Actions components are converted
- Notifications are converted
- Menus, lists and dividers and Links are converted

- Pagination is converted

**Form components are converted (2026-10-12):** `checkbox`, `input`, `textarea`, `radio`, `select`, `switch`, `tabs`, `segment-control`, `range` and `icon-picker`, each as the three pages. They share the playground, the toggles, the card treatment and the spacing, so every Form page looks and behaves the same; copy the nearest one (checkbox for a control with Mode, inline menu and tiles, input for fields with sizes and a Breakpoint, switch for light and dark, radio for a group). Only the toggles and variants that the component really has change (no Mode toggle without a dark mode). How they differ from the one-page template:
- **Sections.** The 11 Examples sections, with extra ones after the closest standard one (checkbox: **Tiles** after Variants; segment control: **Motion** after Playground). A component that has no variants or sizes skips them and says so (Icon picker has no Variants, no Sizes; Range has a short Sizes). The old "Anatomy & specs" is split: the numbered **Anatomy** goes on Examples, **Sizes**, **Measurements**, **Design Tokens** and **States** on Specifications.
- **Playground and Variants controls** are the shared components (`btn-group`, `eco-select`, `eco-input`, `eco-range`). Mode is `data-mode-toggle` + `DK.mode(fn)` (the Playground stage is not a `data-mode-stage`: it has its own Mode field). Breakpoint is `data-bp-toggle data-bp-force` + `DK.bp(fn)`; no `body[data-bp]` overrides are left. Size toggles that lose an option on mobile (Input and Select XSmall) are disabled in the `DK.bp` callback.
- **Spec tables are built live** (`DK.tokenTable`, `DK.recipes`, `DK.printCss`); the component's own builder (`cb()`, `field()`, `radio()`, `sw()` …) is copied, not rewritten, so the Playground, the Variants and the States matrix share one markup.
- **Measurements:** padding comes from the real subject. For a control whose space is a **margin** (checkbox, radio) put `data-measure-margin` on the subject (`components/js/measure.js` then reads the margin of the input), with `style="--k:4"` on the `.measure` so a 24px control is readable. A control with no padding or margin (switch, range) has the table only, with a note, like Badge Dot. A tab, a pill segment control, a select and an input measure their real padding; their figure has the Breakpoint toolbar.
- **Anatomy** uses `DK.callouts` on the real component. Where the part is text, pass `box: function () { var r = document.createRange(); r.selectNodeContents(el); return r.getBoundingClientRect(); }` (a `.form-label` is a block, so its own box is the whole row). An element that only exists while it is open (the icon picker panel) is drawn as a static copy built from the component's own classes, `inert`, with a caption saying so.
- **Motion** on a component that animates: a table under Specifications → Motion; the live easing and duration section (`DK.motion`) stays on Examples after Playground (segment control). After the call, remove `ds-section--secondary` from every section and put a `<div class="ds-sep"><hr class="divider" /></div>` before `#motion`: `DK.motion` flips backgrounds for the old alternating layout.
- **In progress** badge (before 2026-10-28 the text was "Not verified with Figma"; the `title` still says why the page has no Figma check; `badge-basic--warning badge-basic--weak` in `.ds-eyebrow-row`) stays on segment control, range and icon picker, on all three pages.
- **Stylesheet order.** `textarea.css` repeats `.form-label` without `.form-label--sm`, so it is linked **before** `input.css` (the docs controls use `form-label--sm`); every other component file after the base files.
- **Grids** in demos use `grid-template-columns: minmax(0, 1fr)`, never `1fr`: an input has an intrinsic width and `1fr` then overflows at 375px.

**Actions components are converted (2026-10-13):** `button` and `button-group`, each as the three pages (`gen_button.py`, `gen_button_group.py`). Same frame, playground, card treatment and spacing as the Form pages; what is specific to them:
- **Button** has 12 Examples sections: the standard 11 plus **Icon buttons** (toggle icons and Close) after Variants. Variants holds the ds-groups Hierarchy, Which variant, With icons, Badge and System buttons and selected; **Combinations** (pairs of buttons) is Layout & Appearance → Alignment. The Usage Do / Don't pairs are all the component itself (one Primary vs two, a short label vs a sentence, an inverted variant vs a normal one on a dark surface).
- **Dark surface, no Mode toggle.** The inverted variants only exist on a dark surface, so there is no Mode field: the Hierarchy figure has a second `ds-fig__stage ds-stage--dark`, and the Playground stage gets `ds-stage--dark` itself when an inverted variant is chosen. A Do / Don't pair about the surface has both stages dark (`pair_cls(..., 'ds-stage--dark')` in `gen_button.py`).
- **Playground groups that do not fit** the 272px controls column are swapped for an `eco-select` with the same options (the script is kept in `button.html`; `eco-button`, Button group, describes the rule). This is why Size, State and Breakpoint show as selects at ~1280px. The group stays visible when it fits.
- **Specifications → States** has three ds-groups: the variant × state matrix (with the Size toggle), the toggle-icon matrix (Size toggle) and the Close matrix. **Sizes** holds the size table, the badge-size table (both built from the `SIZES` numbers in the page script) and the icon-button boxes. **Measurements** shows the padding of a Secondary button per size at `--k:2` with the Breakpoint toolbar; the label inset is in the table, not the figure.
- **Button group** has one size (Small System buttons), so its Sizes section is short, and no Figma component, so **Not verified with Figma** stays on all three pages. A group that is too wide is cut off in a figure (`.bg-fig { overflow: hidden }`), never wrapped. Measurements draw one button of a one-button group.
- **Figma descriptions (2026-10-13).** The usage guidance on the Button page comes from the descriptions on the Figma component set `2007:68126` (read with `use_figma`: `node.description` on the set and on every variant; the variants repeat the set's text per style). It feeds Overview, Variants → Which variant, the Usage Do / Don't pairs (one Primary vs several, a specific Destructive label, Accent is not for “Add to cart”, a variant with enough contrast), the Behavior groups (System selected, Destructive actions) and the Accessibility label rule. **Inverted variants are chosen by context, visibility and contrast, not by background color alone, and are not limited to dark surfaces**: the docs page still previews them on a dark stage, but never says they are dark-only. Re-read the descriptions when Figma changes and update `gen_button.py` and `eco-button` together. The Button group has no Figma description.
- **Button guidance (2026-10-13).** The Button page also carries the guidance on the page: the "When to use each variant" table has three columns (Variant, Use when, Avoid when); **Combining variants** (Variants, with the pair figure `#v-pairs`); **Icon only** (Variants, Behavior); **Writing button labels** (Usage, with the long-label and vague-label Do / Don't pairs). **Anatomy** has two figures: the button with an icon, a label and a number badge, and an icon-only button with a dot. Two Do figures are live in Combining variants: a Secondary pair above a System pair with trailing icons (`select_all`, `deselect`), and the real **E-Com Toast** card (`ecom-toast--cart`, from `notifications.css`, linked on that page only through `head_extra` in `gen_button.py` / `build.py`, **before** `button.css`: `notifications.css` has its own `.btn` base and would shrink every button to 32px if it came after) with Blank and Primary buttons, as in `eco-toast-ecom`. Placement of the Primary button, stacking and truncation are **Layout** rules and are not on the Button page: Layout & Appearance → Alignment is a "To be added to the Foundations (Layout) page" note. When that page exists, link it from there.
- **Open points** are listed on the pages, not fixed: `ss02`/`ss03` missing on Small; the 6px literals.

**Notifications are converted (2026-10-13):** the hub `notifications.html` and the five types `toast`, `toast-ecom`, `modal`, `banner`, `inline`, each as the three pages (`gen_notifications.py`, `gen_toast.py`, `gen_toast_ecom.py`, `gen_modal.py`, `gen_banner.py`, `gen_inline.py`, shared helpers in `gen/notif.py`). A family with several types, so it follows the Badge pattern: the hub is one page with no tab bar (chooser, decision matrix, status and icon, emphasis guide, dismissing, in action, usage), the type pages are its `children` in `docnav.js`, the breadcrumb is `Components / Notifications / Toast` (`parent` in the generator dict) and each set has only its own three tabs. Same frame, playground, card treatment and spacing as the Form and Actions pages; what is specific to them:
- **Stylesheet order (`pre_css`).** `notifications.css` has its own `.btn` and `.inline-link` base, so it is linked **before** `docs.css` (key `pre_css` in the generator, Examples and Specifications pages): `docs.css` imports `button.css` and `inline-link.css`, which then win for every docs button and link. A bare `.btn` in a notification demo would then be Large, so `notifications.css` has a scoped rule, `:is(.toast, .ecom-toast, .modal, .banner-notification, .inline-notification) .btn`, that keeps every button inside a notification 32px high (XSmall from 769px, Small below) whatever else is on the page. Playground triggers and scenario buttons are docs controls: `btn btn--primary btn--sm` (and the Motion "Show again" button, `btn btn--secondary btn--sm` in `doc-kit.js`).
- **Breakpoints.** The toolbar is Window / Desktop / Mobile (`data-bp-toggle data-bp-force`). `DK.bp` forces the width queries of `notifications.css` (640, 769, 1024, `max-width: 639`, 640–768) against a virtual window: Desktop 1280px, Tablet 700px, Mobile 375px (`doc-kit.js`, `forceBp`; the Tablet value exists but has no button, so tablet values are listed in the Specifications tables, or seen by resizing the window to 640–768px). No page-local `body[data-bp]` copies of component values are left. **Two demo rules remain** (page-local, in `gen/notif.py` and `gen_modal.py`): in forced Mobile a toast, e-com toast, banner or inline notification, and the Modal preview, are capped at 375px (`body[data-bp="mobile"] …`), because in real use they fill the window, and a docs figure is wider than a phone.
- **Sections.** Examples: Playground · Motion (toast, e-com toast, modal, banner, inline: `DK.motion`; the Modal uses `show:` with `showLabel` and `hint`, like the toasts) · In action (toast, e-com toast, modal, inline; the Banner has **Placement and priority** after Layout & Appearance instead, with the placement images and the Axel Bonde AB priority demo) · Overview · Usage · Anatomy · Variants · Sizes · Layout & Appearance · Behavior · Accessibility · Related · References. Specifications: Design Tokens · Sizes · Measurements · Elevation · States (toast, e-com toast, banner, inline) · Typography · Structure · Motion · Behavior · Accessibility Requirements. Code: Basic Usage · the component · API · CSS / Tailwind (`DK.printFile` prints the `@section` blocks of `notifications.css` and `notifications.js`).
- **Previews of fixed overlays.** The Modal is `position: fixed`, so every Examples figure is a static copy (`.modal-preview`, the overlay stripped by `sample()`, z-index auto so it stays under the sticky nav). The real one opens from the Open modal buttons. A toast is fixed too, but a toast sample in a figure is the real element in the flow (`.toast` is not fixed; only `.toast-host` is), so no copy is needed.
- **Measurements** draw the real component (`measureItem()` in the page script builds the `.measure__item`): the toast and the banner or inline `__inner` are the subject; the 2px status edge (a border, or the `__left-border` element) is marked `data-measure-edge`, so the shading starts after it (`measure.js` sets `--edge`, `measure.css` uses it). The Breakpoint toolbar is only on the figures whose padding changes at 769px (e-com toast, modal, banner); the toast and the inline notification have the same values everywhere. The Informational E-Com Toast reads 23px (the 1px edge is inside the 24px), so only the Add to cart toast is drawn.
- **Anatomy** uses `DK.callouts` on the real component (a `.ds-callout__art` with room for the markers); the text of a flex row is marked with a `Range` box (`rng(el)`), because the element is as wide as the row. Markers on the top or bottom edge of a large part use the default `at: 'edge'`; `at: 'center'` only for small parts (icon, ×, image).
- **Do / Don't pairs** per page: a Toast Don't is a Banner for a click, a banner Don't is a Toast, an Inline Don't is a Banner for form feedback, an E-Com Toast Don't is an error shown in it; Weak versus Strong is shown with the component itself.


**Menus, lists and dividers and Links are converted (2026-10-13):** `menu`, `list-item`, `divider` (three pages each) and the Links family: the hub `links-guide.html` (one page, no tab bar: Overview · Which link type · In context · Behavior · Usage · Related · References) with `inline-link`, `action-link` and `tile-link` as its `children` in `docnav.js` (breadcrumb `Components / Links guide / Inline link`, `parent` in the generator dict). Generators: `gen_menu.py`, `gen_list_item.py`, `gen_divider.py`, `gen_links_guide.py` (own hub emitter, copy of the Notifications one), `gen_inline_link.py`, `gen_action_link.py`, `gen_tile_link.py`; the old one-page versions are in `gen/old-source/`. Same frame, playground, card treatment and spacing as the Form and Actions pages; what is specific to them:
- **Playground controls that do not fit** the 272px controls column are an `eco-select` (helper `sel()` in `gen/build.py`): Inline link Size (5) and Color (4), Tile link Content (3), List Item Leading, Trailing and Row. Groups of two to three short options stay button groups; check `scrollWidth` of every `.btn-group` against `.ds-controls` after a change.
- **Menu and List Item.** The row content of a Menu is the List Item, so the List Item page shows its items inside a demo row (`.pg-box`: the Menu hover fill and the row padding from tokens), as the container would draw them. Menu **Measurements** draw one `.menu__item` as the subject (padding 16px left and right, none top and bottom; the row height is a minimum height, so it is in the table); List Item has no padding of its own, so its Measurements are a table with a note, like Switch. The Menu Anatomy puts the Row and Label markers on the left and the Divider marker under the last row, so no line crosses the text. A Menu has no motion of its own (the opener opens it), so Specifications has no Motion section.
- **Divider** has no sizes, states or breakpoint: Specifications is Design Tokens · Sizes · Measurements (table, with a note) · States (one sentence) · Structure · Behavior · Accessibility Requirements, with no Breakpoint control anywhere. Its Do / Don't pairs are the divider itself (a line between every related row, margin on the divider).
- **Links.** The three types share a Do / Don't pattern built from the live components: Inline link (link the words that name the destination, keep it inside the sentence), Action link (own line, one weight in a group), Tile link (not the main call to action, one size in a group). **Checked against Figma 2026-10-13** (metadata of all four frames and the design context of the key variants), so the Links pages have no Not verified badge any more. The Inline link, Action link and Tile link pages do not say what is or is not in Figma (removed 2026-10-14 at the user's request: "Not in Figma" marks, "added here", Figma columns and "checked against Figma" notes do not belong on the page; the same goes for the CSS comments and the three skills). What stays is the source reference that helps find the component: the Figma link in each page intro and the node ids and the Figma description in each skill; the Figma-to-CSS weight conversion note (Figma is 100 higher) also stays. The weight modifiers have the same names on all three types (`--weight-medium`, `--bold`) and `--italic` exists on the Inline link and the Tile link only (never documented for the Action link, 2026-10-14); each page has a Weight (and style) group in Variants and a table in Typography; Inline link also has `--reverse` (Figma `Reverse=yes`). Action link always has an icon, left, right or both (Figma; the playground has one Icons group Trailing / Leading / Both; the icons are called leading and trailing, never left and right, and a link without an icon in a text is the Inline link, also with `--reverse`). Sizes, colors and paddings that change at 769px have the Breakpoint toolbar (`DK.bp()`); the old `body[data-bp]` copies are gone. The inverted variants (Inline link, Action link) have no Mode toggle: the Inverted figure has `stage_cls='ds-stage--dark'` (a new optional argument of `fig_one`) and the Playground stage turns dark when Inverted is chosen. Tile link **Measurements** are real figures (`.tile-link__inner` as the subject, four size/placement items, Breakpoint toolbar: the padding is 10/8/8/6px vertical on desktop and 9/9/6/6 on mobile). Inline link got the same 2px focus ring as the other two types (`body.keyboard-nav .inline-link:focus-visible`, not in Figma, added on request). Fixed after the Figma check: the Action link hover token is `text-action-secondary-hover` and the Tile link White and Grey surfaces are `surface-action-2` and `surface-raised-secondary`, as in Figma (same values as before); XLarge Inline link is in Figma.


**Breadcrumb is converted (2026-10-19):** Figma has two components, **Base** (one crumb: Breakpoint × Enabled / Enabled Hover / Active) and **Bar** (2 to 6 crumbs, with separator and 16px padding), so Breadcrumb follows the Badge pattern: hub `breadcrumb.html` (one page, no tab bar: Overview · Which part · In context · Behavior · Usage · Related · References) and the sets `breadcrumb-base` (a component, child of the hub in `docnav.js`, breadcrumb `Components / Breadcrumb / Breadcrumb Base`) and `breadcrumb-bar`, each as the three pages. **Bar is a pattern (moved 2026-10-19 at the user's request):** it is composed of crumbs, separators and the page spacing, so it sits in the **Patterns** group in `docnav.js` (not under the hub), has a live card first in the Patterns section of `components-overview.html` and `index.html`, eyebrow `Patterns · Navigation`, breadcrumb `Components / Patterns / Breadcrumb Bar` (`parent=('../components-overview.html#patterns', 'Patterns')`); the hub still explains both and marks them (component) / (pattern). File names are unchanged. Rule of thumb: a part built from several components of one kind plus layout rules is a pattern; its single building block stays a component. The explanation lives in `components/patterns-overview.html` (2026-10-19, hand-written, one page, no tab bar, built like a Resources page; first item of the Patterns group in `docnav.js`, linked from the Patterns intro in both overview pages): component vs pattern table, how to tell, how a pattern is built (ECO only, document the arrangement, same three pages, states linked to the component) and the list of patterns. Update it when a pattern goes live or the rule changes. Generators: `gen_breadcrumb.py` (own hub emitter, copy of the Links guide one), `gen_breadcrumb_base.py`, `gen_breadcrumb_bar.py`, shared builders and the page script (`crumb()`, `sep()`, `bar()`, `barMarkup()`) in `gen/bc.py`; the old one-page version is in `gen/old-source/breadcrumb.html`. The "Not verified with Figma" badge is gone (checked against Figma 2026-10-19). Specific to them:
- **Docs stages zero the real page spacing.** `.breadcrumb` has page side padding and an extra bottom padding, and the bar row has 16px padding; in a docs stage these are zeroed page-locally (`bc.py` `STYLE`), and the Measurements figure turns the 16px back on (`.measure .breadcrumb__bar`) and uses the real `.breadcrumb__bar` as `.measure__subject` (a Base measures the crumb itself, scaled `--k:2`).
- **Breakpoint.** Both have the Breakpoint toolbar (`DK.bp`): crumb 12/12 and padding 6px 7px below 769px, 14/14 and 9px 10px from there (heights 26 and 34px; checked at 375, 700 and 1280px). The Base Sizes figure shows both sizes at true size with inline values (docs only), because one window has one breakpoint.
- **Typography.** The 12/12 and 14/14 pair is `label-sm`; the Figma letter spacing differs from the token (open point, listed in `eco-breadcrumb`). The weight of the current crumb is 600 in CSS (Figma Bold).
- **Figma draws the hover crumb as a `button`**; in code every parent crumb is a link (it navigates), noted under Accessibility Requirements of the Base.
- Usage Do / Don't pairs are built from the real crumbs and bar: short label vs sentence, current page not a link, a trail in the bar vs one loose crumb, slash vs chevron, no bar on the home page.

**Layout and content is converted (2026-10-14):** `section` and `collapsible`, each as the three pages (`gen_section.py`, `gen_collapsible.py`; the one-page versions are in `gen/old-source/`). Same frame, playground, card treatment and spacing as the Form pages; both keep the **Not verified with Figma** badge on all three pages (no Figma component). What is specific to them:
- **Section** has no sizes or states: **Sizes** is a pointer to Specifications → Sizes (padding tables for first and other sections at the five breakpoints, with the row for the window width marked, plus the side margin, the page divider and the My Pages title block). **Variants** holds Surface, Position, Zeroed padding (the five cases), Page divider (two live stages) and My Pages title block. **Anatomy** marks top padding, bottom padding, surface and content container with `box` functions that return the padding strips of the real section. Demos set `--px-full` on the figure wrapper (`.sec-fig`, 24px; the measure figure uses `var(--px-page)` in a 280px figure), because the docs' own `--px-full` is far too wide. **Measurements have no Breakpoint toolbar**: `forceBp` only switches at 769px and the section changes at 640, 769, 1024 and 1281px; the figure re-measures on resize and the Sizes tables list all five. Unlike most components, `sm` has its own padding. The padding values are spacing tokens (`space-16` … `space-80`), but `section.css` still writes pixels (open point on the Design Tokens page).
- **Collapsible** was rebuilt from Figma on 2026-10-14 (nodes `535:15947`, `3375:138321`, `8657:125202`, `23386:26225`), so it has **no Not verified badge**. One `markup(o)` builder in the page script (shared by all three pages) writes the row for the Playground (Size, Boxed, Theme, State, Row, text fields and one toggle per header part, with a live warning when a switch and a chevron are both on), Variants (header content, switch, size, boxed, theme, disabled, and the content compositions Text / Checkbox list / Support / Boxed expanded), the States matrix (Breakpoint, Size, Theme toolbar; Enabled/Hover/Disabled × Closed/Open) and the Code recipes (`printable(o)`). Breakpoint field (`DK.bp(refit)`: `refit()` re-sets `max-height` of open rows, a docs-only helper; the real component sets it once on opening, listed as an open point) and a **Motion** section from `DK.motion` (prefix `co`, `always: true`, after Playground; then `ds-section--secondary` is removed and a `ds-sep` placed before `#motion`). Anatomy has two figures (header with all parts, open row). `collapsible.css` hides the last row's line when its list ends a `section` (`section > *:last-child .collapsible-wrap:last-child`), which every docs section matches, so demos carry `.co-lines` (page-local override); the two Placement figures show the rule on purpose. Anatomy turns off the row's transitions (`.co-anat`). A header with a switch is a `div` and has no chevron (a `button` cannot hold a switch); Figma shows both together, listed as an open point.
- **Patterns and Storyblok groups (2026-10-15).** `docnav.js` has two more groups under Components. **Patterns** (composed solutions such as Hero banner, Splash card carousel; placeholders with `soon: true` render as disabled text until the page exists; same structure as the Supernova docs). **Storyblok**: one link per component to its `<name>-storyblok.html` tab (item flag `sb: true`, matched on the full file name so it is the highlighted item on that page). Add a row there when a component gets a Storyblok tab. A pattern with real pages: replace the `soon` item with `c('hero-banner', 'Hero banner')`; Breadcrumb Bar is the first live pattern (2026-10-19).
- **Drafts and Documentation (2026-10-15).** Two different things, split on purpose. **Role tier card** is the one Draft (an experiment, no Figma component): it sits in the **Drafts** group (hub card in `index.html` and `components-overview.html`, group `Drafts` in `docnav.js`), is **converted to the three pages** (`gen_role_tier_card.py`; eyebrow `Drafts · Cards`, badge **Experiment** on all three; no Breakpoint control because the card changes at 640 and 769px and the control only switches at 769px; the demo stages are narrower than the window, so `#pg-host` stacks the pair with a page-local rule) and when it becomes official you move it to its group and drop the Drafts eyebrow. **Docs table** (renamed from `Table`, skill `eco-docs-table`) is **not a component**: it is the table of these documentation pages, so it left the component structure and lives at `foundations/docs-table.html` (file path unchanged) as an **internal docs pattern** (2026-10-28: removed from `docnav.js` and `components-overview.html`, linked only from the section **ECO docs – internal** at the bottom of the root `index.html`; nothing in `foundations-overview.html`). It stays **one page** (eyebrow `Docs internal`, badge **Docs only**, `data-ds="component"` kept for the card treatment, `docnav.css`/`docnav.js` loaded) and is **not** converted to three pages; do the same for any future pattern that exists only for the docs (it goes in the ECO docs – internal section of the root `index.html`, never in the docs nav or Components). Links to it from component pages use `../foundations/docs-table.html`. The product table component is planned; `components/css/table.css` keeps its name because the page templates link it.
- **Do / Don't figures (Usage → When not to use).** One `ds-figs` pair per rule, built from live components, never screenshots. The **Do** figure shows this page's own component in a correct case. The **Don't** figure shows **another** component used wrongly for the same job, so the two figures never show the same thing, and the caption points back to this component or its right sibling: Checkbox Don't = radio buttons for multi-select ("Use checkboxes instead"); Radio Don't = checkboxes for a choice between options ("Use radio buttons instead"); Select Don't = a long list of radio buttons ("Use a select instead"). When the misuse is the component itself (a switch with a Save button, a placeholder used as the label, a mixed state on a single checkbox, long tab labels, a red border with no message) both figures show this component, one right and one wrong. Captions are one sentence, start with "Do …" / "Do not …", and a Don't names the right alternative with "instead" when there is one. Put each pair under its own `h3` (plain `ds-h3`, not `ds-group`) with one sentence of reason above it. Typical pairs to consider: a group with and without a `legend`; a default preselected or not; an error with a message and icon or a red border alone; a short label or a long one; a visible label or a placeholder as label; the state in the label ("On"). Build the figure so it fits the 253px a figure has at ~1024px: the Do figure must not be cut off by overflow either (Tabs: three short tabs, not four). Do and Don't figures sit in the Usage section; the Do / Don't **rules** cards (`rules()`) stay at the end of Usage.
- **Docs cards (2026-10-28, in progress).** `foundations/docs-cards.html` (internal docs pattern next to the Docs table, linked only from the root `index.html` section ECO docs – internal; one page, badge **In progress**) documents the two card layouts the docs start page had: the **Foundations card** (`a.ds-card`, whole card is the link, `.ds-card__visual` with `aria-hidden` and a live mini visual from tokens: `.mini-swatches`, `.mini-type`, `.hx-cols`, `.hx-space`, `.hx-elev`, `.hx-track` + `.hx-dot`) and the **Components card** (`div.ds-card`, a working ECO component in the visual, `.action-link` to the component page; never a link because the visual holds controls).
