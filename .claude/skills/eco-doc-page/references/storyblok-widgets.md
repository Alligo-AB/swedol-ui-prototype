**Hero banner widget (Storyblok group, four tabs, 2026-10-21).** The Storyblok widget group has one widget that is larger than one tab: `components/hero-banner-widget*.html` (Design / Usage / Reference and Examples / Storyblok), built from the Supernova docs and the Figma anatomy frames by `gen/gen_hero_banner_widget.py`. It uses the **custom page set** of `build.py`: `pages=[dict(kind, suffix, label, lead, secs, js), …]` replaces the fixed Examples/Specifications/Code/Storyblok tabs (tab bar, breadcrumb, title suffix and scripts follow `pages`; the first page's title is the plain title, the others get `: <label>`). `docnav.js` strips `-usage` and `-reference` too, and a Storyblok-group item (`sb: true`) is current on every page of its set. Images: `images/hero-banner-*` (`banner-*`/`page-*` jpg examples, `sb-*` Storyblok screenshots, `anatomy-*` Figma frames). Markers: anatomy figures use `DK.callouts` on the image (positions in the 672×350 px frame of the Figma export; below 769px the figure scrolls sideways so the markers keep their spacing); Storyblok screenshots use `sbshot()` with `badge-number` pins at percent positions from `gen/hero_pins.py` (re-check them with the contact-sheet method: draw the pins on the crop, look, adjust). Other overview cards: `components-overview.html` Storyblok section. The Supernova text is kept in meaning, shortened and edited for the ECO voice; `Component status` is not copied.

**Hero banner widget: later rules (2026-10-21).** (1) **Figma over Supernova:** measurements, colors, logos and graphics come from the Figma frames the user links (read them with the Figma MCP, server id may differ from `figma`: `ToolSearch` "figma get_design_context"; never conclude it is disconnected from one failed search); Supernova text is only for wording and guidelines. Figma sources: hero sizes `16892-132478`, Power Deal border `16448-139687`, logos `1473-44183`, news badge `16973-133757` (file `42MgqJjV9vfplwQnrUB62r`). Real assets are saved in `images/` (`hero-banner-power-deal-logo-*.svg`, `-border-*.svg` with the Figma backdrop rects removed, `hero-banner-news-*.png` cropped from Supernova because the badge is not exported). (2) **Measurements section** (Large/XLarge vs XSmall; Medium and Small not read yet); Figma has no XLarge frame, XLarge uses Large. (3) **Legends use the number badge:** `badge_list([(label, title, text)])` in `gen_hero_banner_widget.py` (round `badge-number`, labels like `3a`, `2*`), numbers on the legend match the markers on the picture exactly. (4) **Callout badges in one column:** `DK.callouts` (`doc-kit.js`) accepts `len` as a function(rect); the Hero banner figures use `col(img)` / `colR(img)` so every badge has a 24px gap (36px to the badge centre) to the picture edge in all figures. Check alignment by measuring `.ds-callout__pin` positions, not by eye. (5) Markers on Storyblok screenshots: positions in `gen/hero_pins.py`; a screenshot that already carries its own badge (`horizontal`, 4b) gets no pin.
**Figure spacing (measured on `components/collapsible.html`, 2026-10-21):** a figure (`.ds-figs`) is followed by 48px before its list or next heading; a numbered list is followed by 32px before the next heading. The Hero banner set uses 48px figure → list and 48px list → next figure (`.hb-legend`).
**Anatomy list spacing (2026-10-21, supersedes the line above for numbered lists):** the numbered list under an anatomy figure sits 32px below it (24px mobile); `docs.css` rule `.ds-prose > .ds-figs + .ds-bullets--num`. Other blocks after a figure keep 48px.
**Anatomy list spacing, final (2026-10-21, from the user's annotation; replaces the 32px line above):** figure → its numbered list **16px**; numbered list → next figure **40px** (`docs.css` `.ds-prose > .ds-figs + .ds-bullets--num` and `.ds-bullets--num + .ds-figs`; Hero banner `.hb-legend` the same).
**Note boxes (`note()` in the Hero banner generator, `.hb-note`, 2026-10-21):** body-md text (16/22, 17/24 from 769px) on the light grey `--color-surface-raised-secondary`, the same grey as the figure stages. Use the same for any short explanatory note box.
**A link is as big as its text (2026-10-21):** inside a text block the `inline-link` size must equal the surrounding body size (body-md 16/22 → `inline-link--medium`; ds-desc 18/24 → `--large`). In the Hero banner generator `note()` swaps `--large` for `--medium`. Verify with computed font-size of every `a.inline-link` against its parent (script in the session log: 0 mismatches on the four Hero banner pages).
**Screenshots with a transparent shadow edge (2026-10-21):** save them as PNG with alpha, never `convert('RGB')` to jpg (the transparent shadow pixels turn black and give a dithered black border). In the Hero banner generator `imgsrc()` picks the `.png` when it exists and adds `.hb-alpha` (light grey `--color-surface-raised-secondary` behind, no border), so the shadow shows as in Supernova.
**Image weight and equal heights (2026-10-21):** the Hero banner screenshots are WebP (`hero-banner-page-*`, `-width-*`, `-sb-*`; quality 82, alpha kept): 27.9 MB of PNG became 4.1 MB. `imgsrc()` prefers `.webp`. Examples in a `.hb-grid` all get the same height by CSS (`aspect-ratio: 1139 / 830`, `object-fit: cover`, `object-position: top`), cropped from the bottom.
**Do / Don't with screenshots (Hero banner Usage, 2026-10-21):** four cropped Supernova screenshots (`images/hero-banner-dd-*.webp`) in two `fig_pair()` rows (Do left, Don't right), shown whole (`width:100%`, no `object-fit` crop). Never push a wide banner into a fixed-ratio `cover` box: it crops the sides.
**Heading spacing (Hero banner set, from the user's annotation 2026-10-21; page-local rules in `gen_hero_banner_widget.py`):** figure with caption → next h3 **16px**; list → next h3 **24px**; h3 → h4 sub-heading **8px**; h4 → picture **16px** (48px looked wrong, changed by the user). Margins collapse: remove the h3's own bottom margin when an h4 follows (`:has(+ .hb-h4)`) or the gap stays 12px.
**Storyblok screenshots with transparent areas (2026-10-21):** composite onto white before saving (`alpha_composite` on a white RGBA, then `convert('RGB')`); plain `convert('RGB')` turns transparent areas black. A screenshot with a large empty canvas (`sb-horizontal`) is cropped to its opaque bounding box. Check every PNG source for `getchannel('A').getextrema()[0] < 250` before converting.
**One picture rule (Hero banner set, 2026-10-21):** whatever sits directly before or after a picture (h2, h3, h4, paragraph, list, note, legend) is **16px** away, in both directions; only a numbered list or legend followed by the next picture gets **40px**. Paragraph/list bottom margins are zeroed when a picture follows, because margins collapse to the larger value. Measure all four pages after changes (script: loop iframes, compare `getBoundingClientRect` of each `.ds-prose` child pair).
**Hero banner in the navigation (2026-10-22):** `docnav.js` lists it twice: **Hero banner** under Patterns (`c('hero-banner-widget', …)`, current on Design/Usage/Reference) and **Hero banner widget** under Storyblok widget (`c('hero-banner-widget-storyblok', …, { sb: true })`, current only on the Storyblok tab; the `sb` items match the full file name). The overview card is in the Patterns section (Design page) and a second card in the Storyblok widget section (Storyblok tab); `patterns-overview.html` lists it as live. Eyebrow: `Components · Patterns`.
**Article Highlight Group Card (Storyblok widget, 2026-10-26).** `components/ah-group-card-widget-storyblok.html`, built by `gen/gen_ah_group_card_widget.py` (custom page set `pages=[…]` with **only the Storyblok page so far**; Design / Usage / Reference and Examples are planned, add them before the Storyblok page in `C['pages']` when the user asks). Workflow that worked: (1) pull the component schema with the Storyblok CLI (`npx storyblok@latest login` with a Personal Access Token, then `components pull --space <id>`; the token is pasted in the terminal, never in the chat) and read field names, types, options, defaults and conditions from `components.json` instead of copying them from screenshots (blocks `article-highlight-group`, `-group-slide`, `-group-card`; `-card-single` and `-card-single-row` are left for later); (2) the user's full browser screenshots `images/AhGroupCard_*.png` are cropped by `gen/crop_ah_group_card.py` into `images/ah-group-card-sb-*.webp` (settings panels by contact-sheet coordinates `tile()`, previews by `prev()`, whole windows by `frac()`; white background, WebP, run it again after changing a crop; look at a contact sheet of the result before building); (3) the picture helpers `shot()` (one narrow settings panel, `.ah-narrow` max 480px), `pair()` (settings left, result right, two columns from 769px, one column below) and `dont()`; headings are numbered in groups (`4a. Image Section`) like the Hero banner set; tables use `table()` with 16px above and below. Docs spacing rules of the Hero set apply (picture rule: 16px, 40px after a numbered list). Marker pins (`badge-number sb-pin`, black) sit on every settings screenshot at the area its numbered heading describes (`4a`, `8c`, …; several pins with the same number when a heading covers more fields), one vertical column per picture, at the left edge next to the field labels (pin centre about 4% from the picture's left edge; each settings crop starts about 40px before the labels to make room, a pin never covers a label or an icon); positions are percent literals in `gen/ah_pins.py` (`AH_PINS`, like `hero_pins.py`), computed from the crop boxes in `crop_ah_group_card.py`: change a crop and the pins must be recomputed. Navigation: `c('ah-group-card-widget-storyblok', 'Article Highlight Group Card', { sb: true })` in the Storyblok widget group; not yet in `index.html` or `components-overview.html` (ask first).

**Number badges on pictures (AH Group Card page, 2026-11-04, rule):** a settings picture shows only the badge number(s) of the heading it sits under, never the numbers of other headings that have their own picture (no 7g to 8c on the 8d picture). The picture of the result (card preview) under the same heading gets the same number next to the element it shows (8d next to the icon of the action link and of the button). Positions in `gen/ah_pins.py` (percent of the picture; a preview picture is pinned by hand, centred on the point).

**Variants of one field (2026-11-04, rule):** when one heading has several variants that each have an example card (Bulletlist: Bullet, Checkmark, Numbered), the chosen option in each UI picture and the matching example get the same sub-numbered badge (`7d-1`, `7d-2`, `7d-3`), and the UI pictures stand in the same order as the example cards. The field itself keeps the plain heading number (`7d`).
