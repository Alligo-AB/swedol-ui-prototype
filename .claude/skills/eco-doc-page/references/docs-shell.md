## Back to top

`docnav.js` also builds one icon button (`btn btn--secondary btn--md btn--icon ds-top`, `arrow_upward`, `aria-label` and `data-tooltip` "Back to top"). It is `position: fixed` 24px (16px below 769px) from the bottom right of the window, so it follows the window edge when the window is widened, and it is hidden until the page is scrolled past 75% of the window height. A click scrolls to the top (instant under reduced motion) and moves focus to the `h1`. The Contents list stops 72px above the bottom so it never sits behind the button. At the end of the page the sticky list also stops **80px above the footer** (`.ds-sidetoc { bottom: 80px }` in `docs.css`), so its scrollbar never touches the footer edge. Styles `.btn.ds-top` in `docs.css` (the extra `.btn` wins over `button.css` loaded later). It loads `tooltip.js` itself when the page does not.

## Links in doc pages

Links in running text are the ECO **Inline Link** (`components/css/inline-link.css`, imported by `docs.css`): `<a class="inline-link inline-link--large" href="…">`. There is no docs-only link class any more (`.ds-link` is removed). The size follows the text around the link: `--large` in `.ds-desc`, `.ds-bullets` (20/28, mobile 18/24), `--medium` in `.ds-note`, `.ds-rule` and figure captions (17/24, mobile 16/22), `--small` in table cells and `.pg-note` (14/20). `--xlarge` in `.ds-lead` (body-xl, 24/32 desktop, 20/26 mobile; not in Figma yet, see `eco-inline-link`). **Colour follows the text:** in grey text (`.ds-desc`, `.ds-bullets`, `.ds-note`, the footer, all `text-secondary`) add `inline-link--secondary`; in `pg-note` (`text-tertiary`) add `inline-link--tertiary`; in black text (lead, tables, Do/Don't, captions) the default. Standalone links (not in a sentence) are the ECO Action Link (`action-link`). The default colour is `text-action-primary`.

## Footer

Every doc page that loads `docnav.js` gets the footer from it (do not write it by hand). Three columns: **How you can help** (text and the Slack channel link, then "Made with ♥ by Alligo E-com © <year>", the year is the current year, the heart is the Material Symbols `favorite` glyph in `--ds-accent`), **Resources** (Storybook, Figma) and **Support** (ECO Slack Channel). Links are the ECO components: every link, in the text and in the three lists, is an Inline Link (`inline-link inline-link--medium inline-link--secondary`, `eco-inline-link`; the footer text is grey); `docs.css` imports `inline-link.css`. Styles: `.ds-footer` in `docs.css`: grey `surface-raised-secondary`, 1px top line, same side margin as the sections (`--px-full`), `2fr 1fr 1fr` from 769px, stacked below, text body-md (16/22, 17/24 from 769px), titles title-sm. Change the text or links in `docnav.js` only. Storybook links to a Chromatic build (`appId=67b6063b450f52d85d87d37f&number=106`: a fixed build number, so update the link in `docnav.js` when it should point to a newer build). Figma links to the ECO Design System file. A page that has no `docnav.js` (the older single pages) has no footer until it gets the navigation.

## Hub (`index.html`, start page, rebuilt 2026-10-27)

The start page of the docs site (old version kept as `index_old.html`). Hand-written, page-local CSS with the `hx-` prefix, in the docs frame (`docs.css`, `docnav.css`, `docnav.js`). **All paths are root-absolute** (`/eco-design-system/…`, `/components/…`, `/hairline/…`): `npx serve` redirects `/eco-design-system/index.html` to `/eco-design-system` without a slash, which breaks relative paths (see the warning at the top). Sections in order:

1. **Hero** (`.hx-hero`, `--color-surface-100`, revised 2026-10-27 after get.section.express): **fills the first screen** (`min-height: calc(100svh - --hx-top - --hx-bottom)`, measured by the script: below the fixed mobile bar, inside the 16px frame on desktop), flush with the panel top (`margin-top: -var(--pt-page)`), **no breadcrumb** on the start page (it is Home). Content centred: eyebrow badges, `.ds-title`, lead, search field, two Action links Large (inverted, leading icon); live counts are in the section links (foundations and component pages from `window.ECO_NAV`, tokens parsed from the package). Behind it a **tilted grid of vertical columns** (`inset: -20%`, `rotate(-8deg) scale(1.2)`, gap `space-16` / `space-48` from 769px; **fixed 300px columns** (the figure stage width), the script builds as many as cover the field and adds/removes columns on resize, so the gaps never grow on wide screens (2026-10-28; about 2 at 375px, 5 at 1280px, 8 at 1920px); new columns are mounted with `window.HLmount` from `embed.js`) of Hairline figures (`hairline/*.js` via `embed.js`, no tour) with no plate (`.hx-tile` has no background and `overflow: visible`, so the figures float on the dark field; 2026-10-27); odd columns run up, even down, `--duration-loop-slow` (90s) linear. Tiles reuse `.ds-card__visual--hairline` so the per-figure offsets of `hairline-card.css` apply. No pointer arrow in the hero figures: `[data-part="cursor"]` and the white halo some figures draw right before it (`path.fo:not([data-part])`) are hidden under `.hx-tile` only; the overview cards keep their cursor (2026-10-28). Shade = `--color-surface-opacity-black-80` + a top/bottom vignette (gradient between `opacity-black-50` and `opacity-white-0`). Premium extras (2026-10-27, `components/css/premium.css`, provisional tokens listed in `figma-sync.md`): `.fx-edge-blur` (md+), `.fx-grain`, scroll-out of the content and pointer parallax of the grid (md+, see `eco-motion` rule 11). Bottom: scroll cue (`btn--blank-inverted btn--sm btn--icon`, `arrow_downward`, to `#foundations`) centred, pause/play (`btn--secondary-inverted btn--sm btn--icon`, WCAG 2.2.2) right, both with `data-tooltip`. Entrance: eyebrow, title, lead, search, links rise in one after another (`duration-slow-4`, `ease-decelerate-emphasized`, stagger `duration-fast-4`); the grid fades in. `html.hx-motion` is set in `<head>` so nothing flashes.
2. **Foundations**: an entry row (`a.hx-entry`, text 5fr + dark `.hx-panel` picture 7fr from 769px): h2, description, `action-link` "Explore the foundations"; the picture is an abstract inline SVG (`.hx-art`, 640×360) built from tokens only (grid lines `surface-70`, white lines, Swedol/Tools accents).
3. **Components** (2026-10-28): h2 + description, then a row of three `a.ds-card.hx-dest` cards with a dark `.hx-panel` picture on top: **Components** (wide, `#components` of `components-overview.html`, 640×360 art), **Patterns** (`#patterns`, a page assembled from blocks with one lifted out) and **Storyblok** (`#storyblok-widgets`, editor fields flowing into a finished block), both 320×360 art in the same `.hx-art` style. Grid 1 column below 640px (all pictures 16:9, art centred), 2 columns 640–1023px (Components full width), `2fr 1fr 1fr` from 1024px so all three pictures are equally high. Hover: no darker frame, the action link gets its hover state (shared rule with `.hx-role`). **Colour rule for these abstract pictures (user, 2026-10-28):** the ECO docs accent orange (`--ds-accent`) leads (the big shapes); Swedol green (`--color-accent-default`) and Tools red (`--color-primitive-color-brand-tools-accent-brand`) are small details. When two colours sit edge to edge as a brand pair, use Tools red + Swedol green (never orange in the pair). This mix is for the documentation only; products never mix the brands' colours (see `eco-colors`, brand separation).
4. **Three pages**: a real `tab-bar--secondary` (content tabs) switching between Examples & Guidelines / Specifications / Code, with links to the Button set; note about the Storyblok tab.
5. **Who is it for?**: four role cards (designers, developers, project managers, then **UX copy** last as a disabled card: a `div` with `.ds-card--soon` and a "Coming soon" `badge-basic--neutral-grey badge-basic--weak`, no link, until there is a UX copy guide; 2026-10-28).

## Site navigation: Navigation Rail + Secondary panel (draft, desktop ≥961px only)

`eco-design-system/docnav.css` + `docnav.js` build a fixed 88px Navigation Rail (home, Search, Foundations, Components, dark mode) and a 332px Secondary navigation panel from one page list inside `docnav.js` (add a new doc page there, with its group). Load `docnav.css` after `docs.css` and put `<script src="…/docnav.js">` directly after `<body>`. Used so far by `tooltip*.html`, `index.html` (start page, rail only; reads `window.ECO_NAV` for its counts), `components-overview.html`, `foundations-overview.html`. **Group labels in the panel (2026-10-27):** `.dn-group` is `text-secondary` (not tertiary), with an inset 1px `--color-border-secondary` line above it (margin 8px 24px, padding 16px 0 4px; mobile drawer margin-left 44px, margin-right 16px) on every group except the first (the one right after the overview link), and the items under a label are indented 16px (links 41px, sub-pages 56px; mobile 60px and 76px; the Component Overview link stays at 25px / 44px). Row height (48px) is unchanged. Check at 375/700/1400px. **Trial (2026-10-28):** `panelHtml` drops the group labels and lists every item A-Z after the overview link (overview stays first); only **Storyblok widget** and **Drafts** keep their labels, in that order at the bottom. Duplicate hrefs show once. Group titles stay in `NAV` (search, start page). **Overview link (trial 2026-10-30):** the first row of each panel (`.dn-item--overview` / `.dn-link--overview`) is the category's start page and is set apart: the category's rail icon in `--ds-accent` (filled when current) before the label, no arrow (removed 2026-10-30); on hover the label moves 4px right, like every link label in the panel (`.dn-link__t`, desktop, off under reduced motion; 2026-10-30), and a full-width 1px `--color-border-primary` line directly below the row, no gap (edge to edge in the panel; gap removed 2026-10-30). In the framed layout the panel has `padding-top: 16px` at every width, so the overview row's top edge lines up with the content panel's top border (2026-10-30). Mobile drawer: 20px icons, the icon sits under the back arrow (padding-left 16px + 20px + 8px gap), so the label still starts at 44px.
- **Resizing the window across 1600px (2026-10-14):** the pinned panel is slid by `docnav.js` with Web Animations (`duration-medium-2`, 300ms, shortened from 450ms at the user's request; `ease-decelerate-generic` in (tried: emphasized, judged too sharp at the start), `ease-accelerate-generic` out: eco-motion says a removed element accelerates; `ease-in` was used first because a token name that does not exist, `ease-accelerate-emphasized`, was referenced), because the CSS transition's `visibility` delay left the panel invisible while the page had already moved (a white strip on the left). `--dn-offset` is registered with `@property` (`<length>`) and `html.dn-anim` (set when the navigation is ready, never on page load) transitions it, so the page glides instead of jumping: when the panel comes in it leads and the page follows after 60ms (`duration-medium-2`, `ease-decelerate-generic`, so it settles with the panel); when it goes out the page moves first (`duration-fast-4`, `ease-decelerate-emphasized`) and the panel follows, so no white strip shows. Reduced motion: no animation.

## Framed layout (docs shell, from 961px)

`docnav.js` adds `html.ds-frame` on every page that loads it; rules are in `docnav.css` ("Framed content"). `html` is the grey surround (`--color-surface-02`), `body` the white panel (border 1px `--color-border-primary`, radius 16px, margin 16px, `overflow: clip` not `hidden` so sticky keeps working, and `html { overflow: auto }` so the clip is not passed on to the viewport, which would stop scrolling). `--px-full` is reduced by 17px for the margin and border. The footer is appended to `html` (not `body`) on desktop so it sits on the grey; it needs its own `font-family`. Rail and panel are `--color-surface-02`, hover `--color-surface-05`; the rail has a right border only while a panel is shown (open, or pinned from 1600px). The hover panel has no shadow, a drawn right edge (`--dn-line` set by `docnav.js` on scroll) and the corner piece `.dn::after` (z-index below the rail, so it slides in behind it). The scrollbar of that panel is a styled webkit one that starts below the corner (`scrollbar-width` must be `auto` for it to apply).
