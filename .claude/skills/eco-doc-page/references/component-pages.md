## Component pages

**Every component page is three pages** (`<name>.html`, `<name>-specifications.html`, `<name>-code.html`, see "Split component pages" below). Reference implementation: `components/tooltip.html` + `tooltip-specifications.html` + `tooltip-code.html`. **New page:** copy those three. **User asks to update or rebuild an existing one-page component page:** convert it to the three pages ("Moving a page" below); do not ask first, say what you moved. Keep the specification in the component's `eco-*` skill (link to it in the intro). The Form components (below) are the reference for form controls: playground, toggles, states matrix and card treatment.


**Sections (in this order)**, each with a sticky-nav chip:
1. **Playground**: `.ds-playground`, a live stage plus controls: Mode (light/dark, only if the component has a dark mode), Size, Type/variant, Value, State, label text and a Breakpoint toggle when the Figma axis changes anything. Below it a copyable **markup for this selection** that updates with the controls. The component in the stage is real: click and tab to try it.
2. **Variants**: every variant and size as real components in `.ds-stage` blocks (sizes, with/without label, group, special patterns such as select-all, inline/menu type, table use). One Mode toggle (and Breakpoint toggle) at the top syncs every stage.
3. **States**: a `.ds-matrix` table, rows = states, columns = values (for example unchecked / checked / mixed), with Mode, Size and Type toggles. Every state in Figma appears; a state Figma does not define shows `.ds-na` "Not defined" (and is explained in a note), never an empty cell.
4. **Anatomy & specs**: an `.ds-anatomy` diagram at 8× scale with a legend, a sizes table, a **token table resolved live** (`getComputedStyle(documentElement).getPropertyValue('--color-…')`, with a `.ds-dot`), and a behavior / accessibility table (click, Tab, Space, disabled, label).
5. **Code**: one copyable `.ds-code` block per recipe (standard, checked/disabled, dark, group, special cases) and one for the **CSS, fetched live from the shared `components/css/<name>.css` that the page links** so it can never drift from the examples.
> **Tailwind block (all component pages):** `eco-design-system/tailwind-note.js` appends a "Using with Tailwind" block at the end of the Code section (or the last section on pages without one): the component CSS goes in `@layer components`, tokens are used as `[var(--…)]`, `md` is 769px. Include `<script src="../tailwind-note.js"></script>` before `subnav.js` on every new component page.

6. **Usage**: a "which component" table (this one vs its siblings, for example checkbox / radio / switch) and the Do / Don't cards.

**How to build it**
- **One builder function** creates every example (`cb({dark, small, menu, checked, mixed, disabled, state, label, aria})`-style) so playground, variants and matrix always use the same markup.
- **Component CSS lives in `components/css/<name>.css`** (repo root, shared with prototypes and products), linked from the page with `<link rel="stylesheet" href="../../components/css/<name>.css">`. Not in `docs.css`, not in a `<style id>` block in the page: it is the component, and the Code section fetches and prints the same file (use `DK.printCss(pre, name, strip)` from `doc-kit.js`; a component with two files, like Select, fetches both). Behaviour JS the same way in `components/js/`. Force hover/focus for the matrix with `:is(:hover, [data-state="hover"])` pairs; the Code section strips the `[data-state]` half before printing (`replace`).
- **Mode, Breakpoint and other global toggles** are `[data-…-toggle]` groups that all stay in sync (`aria-pressed`); the choice applies via a class on the stages or a `data-bp` attribute on `<body>`. A Breakpoint toggle (Window / Desktop / Mobile) only previews what the component does by itself at 769px: it forces the values with page-local CSS and is never part of the component CSS.
- **Mobile**: mobile styling below 769px (`sm` looks like mobile), the Breakpoint axis in Figma = Desktop (769px+) / Mobile (below 769px).
- Page-local CSS is only layout (rows, columns, group spacing) and the state-forcing for the demo; no component or token values.

## Split component pages: Examples & Guidelines / Specifications / Code

**Adopted (2026-10-12).** Component pages are **three pages**: `components/tooltip.html`, `tooltip-specifications.html`, `tooltip-code.html` are the reference implementation. New component pages are built this way; an existing one-page component page is converted to it when the user asks to update or rebuild it. Foundation pages are migrated one at a time (Colors and Layout done 2026-10-22, see "Foundations in the new structure"; typography, elevation and motion are still single pages). **A component with several types** (Badge: Basic, Dot, Number, Product & Discount, Purchase Info) gets a **hub page** `<name>.html` (one page: Overview, Usage, Color, Emphasis, with a table of the types) and one three-page set per type, `<name>-<type>.html`, `-specifications.html`, `-code.html`, with the type pages as `children` of the hub in `docnav.js` (the Links guide pattern) and the breadcrumb `Components / Badge / Dot`. The hub has no tab bar, and it must not get tabs to the type pages (decided 2026-10-12: the side menu and the table of types on the hub are the way to the type pages); each type page set has only its own three tabs (`aria-label="Badge Dot"`). The old one-page Tooltip pages are deleted.

| Page | File | Holds |
|---|---|---|
| **Examples & Guidelines** | `<name>.html` (the overview card links here) | The 11 sections below |
| **Specifications** | `<name>-specifications.html` | Technical values |
| **Code** | `<name>-code.html` | How to use it in code |

**Page frame.** Breadcrumb (on the sub pages `Tooltip` is a link and the page name is the current item), intro (`.ds-section--first`), then `<div class="ds-tabs"><nav class="tab-bar tab-bar--primary" aria-label="<Component>">` with three `<a class="tab">` (eco-tabs link tabs, `aria-current="page"` on the current one; the same `aria-label` on all three pages so the line slides across the page load). Link `/components/css/tabs.css` and put `/components/js/tabs.js` in `<head>`. Then `<div class="ds-doc">` holds all sections, and the page ends with `toc.js` **before** `subnav.js`. The tab bar's design is the eco-tabs default and may change later.

**Contents navigation (built by `toc.js`, no markup to write).** Level 1 = each `section.ds-section[id]` (its `.ds-h2`), level 2 = each `.ds-h3.ds-group` inside it (given an id when it has none). A plain `.ds-h3` is not listed (a third level is an open question). From 1024px a sticky "Contents" list sits in the right margin (`.ds-sidetoc`; the item in view is marked with `aria-current`, the list scrolls by itself if it is taller than the window) and the sections get `padding-right: calc(var(--toc-w) + var(--toc-gap))` (list 192px + 40px gap, `docs.css`). From 1024px the whole block (1200px text + gap + list) is centred beside the navigation, so both side margins are equal (`--px-full` is set from that block in `docs.css`, for pages with `.ds-doc`). Below 1024px the existing chip row (`.ds-subnav`, sections only) is built instead. So in the content: **section title = `.ds-h2`, sub-heading that belongs in the list = `h3.ds-h3.ds-group`, anything smaller = `h3.ds-h3`**. Sections alternate white / `ds-section--secondary` (the split pages are all white with dividers, see the layout below). Do not add `DK.motion` or `DK.callouts` expecting a hand-written subnav chip: pages with `.ds-doc` do not have one.

**Jump to a `#hash` (`toc.js`, `docnav.js`, `docnav.css`, 2026-10-14).** Page content is built by scripts after load, so the browser's own jump to `page.html#id` landed above the target. `toc.js` jumps again when everything is built, after fonts and images have loaded, and once more 400ms later (the late font swap moves the layout); it stops correcting when the reader scrolls. **Arrival from a link on another page of the docs** (any link, with or without a `#hash`: a card on the start page to a landing page, a Contents link, a panel link; same site, other page, read from `document.referrer`, and the navigation type must be a link click: reload and back/forward are excluded; without a hash there is no scroll, the page just fades in at the top; tried 2026-10-14, to be judged by the user): `docnav.js` sets `html.dn-arriving dn-hold` before the first paint, so the content is hidden and the Secondary navigation panel is held back. Sequence: (1) the rail is there; from 1600px, where the Secondary navigation panel is pinned, the panel slides out from the left (`dn-hold` removed and `open(cat)` called: without `is-open` the panel's `visibility` transition has a 300ms delay, so it would pop in without sliding); **below 1600px the panel is not animated** (the overlay stays closed, only the rail shows), the page fades in a moment after the rail; (2) from 1600px after the panel's `duration-medium-2` slide plus 120ms; below 1600px together with the rail's slide (`duration-medium-4`, 400ms, `ease-decelerate-emphasized`; the panel from 1600px uses `duration-medium-2`) (961-1599px the rail slides in from the left, `dn-hold-rail`; the fade starts earlier but keeps its `duration-slow-3` length), and when the page has loaded and fonts are ready, the content fades in (`dn-landing`, `dn-land` keyframes, `duration-slow-3` (defined in `docs.css`: a duration token used in `docnav.css` must exist in `docs.css`, or the whole `animation` declaration is invalid and the fade silently does not run), `ease-decelerate-emphasized`) while the page scrolls the last 120px to the heading; (3) `close()` after the page has settled clears `is-open`; the pinned panel stays. Below 961px there is no rail or panel, so only the fade and the small scroll happen. **Links inside the navigation do not start it** (2026-10-15): a click on a link in the Secondary navigation panel, on any category item in the rail (hovering it has already opened its panel), or on a tab of the component's tab bar (`.ds-tabs a.tab`: Examples / Specifications / Code / Storyblok), sets `sessionStorage` `dn-noarrive` (valid 4s) and the next page loads without the sequence, so the panel does not slide again; a click on the page you are already on (panel link or rail item) is cancelled, no reload. Reduced motion and URLs pasted from elsewhere (no referrer, or the same page): no sequence, the page jumps straight to the heading. A 5s failsafe never leaves the page hidden. Give a heading that others link to an explicit `id` (for example `id="layout-dividers"`), because two headings with the same text get generated ids that depend on their order. The earlier animated variant with a marked heading was removed at the user's request.

**Heading anchors (built by `toc.js`, no markup to write).** Every heading in the Contents list (`.ds-h2` and `h3.ds-group`) gets a Blank icon button (`icon-btn ds-anchor`, the Material Symbols `link` glyph, `aria-label` "Copy link to <heading>", `data-tooltip` "Copy link to heading") appended to it. A click copies the URL of that heading (`location.origin + pathname + #id`), sets the hash with `history.replaceState` (no scroll), and shows the ECO success **system toast** "URL to heading copied" (4 s, **Weak**: a routine confirmation is the quiet tier, see `notifications-guide` → "Choosing the emphasis"; the error toast is Weak too). If the browser refuses to copy, an error toast says to copy the URL from the address bar. The toast needs `notifications.css` and `notifications.js`: they are **loaded on the first click** (the stylesheet is inserted before `docs.css`, so docs and component files win over its own `.btn` base). From 1024px the icon hangs in the left margin (`left: -32px`) and shows on heading hover or keyboard focus (the heading's `::before` extends the hover area over the margin); below 1024px it follows the heading text; on touch screens (`hover: none`) it is always visible. Styles `.ds-anchor` in `docs.css` (with `.ds-doc` in the selector, so they beat `button.css`). A plain `h3.ds-h3` is not in the Contents list and has no anchor. **Publishing:** copying needs `navigator.clipboard`, which only works over **HTTPS** (or `localhost`); over plain `http://` the code falls back to `document.execCommand('copy')`, an old API that browsers may remove. Inside an `<iframe>` the host page must allow it (`allow="clipboard-write"`), otherwise the user gets the error toast. The success path has only been verified by reading the code: the preview browser denies the clipboard, so test one real click on the published site.

**Layout of the split pages (shared rules in `docs.css`; only the demo layout of one page stays page-local, e.g. the Tooltip variants grid).** Used as written for every component page.
- *Text and Contents list:* from 1024px the content is up to 1200px wide and the Contents list (240px, 40px gap) sits **outside** it in the right margin (the section's `padding-right` is `max(--px-page, --px-full − 280px)`, the `.ds-inner` is `max-width: 1480px`). Running text (`.ds-lead`, `.ds-desc`, `.ds-bullets`) is as wide as the Playground stage: `max-width: calc(100% − 344px)` from 769px (320px controls + 24px gap). The intro section uses the same frame.
- *Backgrounds and dividers:* all sections are white (no `ds-section--secondary`); between sections sits `<div class="ds-sep"><hr class="divider"></div>` (`.ds-sep` in `docs.css`, link `components/css/divider.css`; same side margins as the sections, ending with the content from 1024px). Top space above the tab bar (`.ds-tabs`): 48px mobile, 64px from 769px.
- *Variants grid:* cells separated by 1px lines like Alignment and Placement (`box-shadow` left and top on each cell, the grid clips the outer ones); an empty 12th cell (`.pg-var--empty`, hidden below 640px) completes the last row.
- *On-page tabs:* `<div class="ds-doc" data-subnav="tabs">` makes `toc.js` build the below-1024px nav as an eco-tabs **secondary tab bar** (`.ds-subnav--tabs`, scrolls sideways, line follows the section in view) instead of chips. The line and the Contents indicator use `var(--ds-accent)` (`docs.css`: `--tab-line-active` on `.ds-subnav--tabs .tab-bar`, border of `.ds-sidetoc__list a[aria-current]`). On such pages `subnav.js` jumps with `ease-decelerate-generic` and one duration step faster (150 / 200 / 300 / 450ms by distance), and stops with the section's divider line under the tab bar's own bottom line (2px behind the bar; at ≥1024px, where only the Contents list exists, the line stops at the top of the window).
- *Spacing:* the gap between a table and the Do/Don't rules is `space-md` (`docs.css`: `.ds-table-wrap:has(+ .ds-rules)`, `var(--dimension-spacing-space-md)`).

**Storyblok tab (optional fourth tab, 2026-10-14).** A component that has a Storyblok widget gets a fourth tab **Storyblok widget** after Code (renamed from "Storyblok" 2026-10-15: tab label, breadcrumb, title suffix in `gen/build.py`, nav group title in `docnav.js`): `<name>-storyblok.html`, breadcrumb `Components / Collapsible / Storyblok`, the same frame, Contents list and tab bar (the tab bar scrolls sideways at 375px). **One widget per tab, on its own component's page:** the Storyblok tab of a component documents only that component's widget (Collapsible's tab covers only the Collapsible block); other widgets are documented under their own components, never together. It documents how an editor sets up the widget (what the widget is called in Storyblok, the steps, the settings and how they map to the component classes), as in the Supernova Storyblok tab. Turn it on in the generator dict with `sb=[(id, html), …]` (and `lead_sb`, optional `js_sb`); `build.py` then adds the tab to all pages of the set and emits the page. `docnav.js` strips `-storyblok` from the current page name. Reference: `gen_collapsible.py` (`shot()` helper). **Annotated screenshots:** the clean Storyblok screenshot goes in `images/storyblok-<name>-<step>.png` (root-absolute `/images/…`), and the numbered markers are real `badge-number` elements positioned in percent on top (`.sb-pin`, `left`/`top` in % of the image, centered on the field row; a red marker `.sb-pin--red` for a step that continues in the next image, as in the Supernova pages; a red rectangle `.sb-box` for a highlighted list item). The numbered legend under the figure is `ol_parts`. A Pro tip is a page-local `.sb-tip` card. `components-overview.html` has four categories, each an h2 section: **Components**, **Patterns**, **Storyblok widget** and **Drafts** (see "Overview pages" for the filters, 2026-10-28). `index.html` still gets its Storyblok section from the user.

**Examples & Guidelines: 11 sections** (skip one only when there is truly nothing to say, and say so to the user):
1 Playground · 2 Overview · 3 Usage (When to use, When not to use, Quick reference) · 4 Anatomy · 5 Variants · 6 Sizes · 7 Layout & Appearance (Alignment, Placement, Width, Appearance) · 8 Behavior (Hover, Focus, Auto placement, Dismissal) · 9 Accessibility (short summary + link to Accessibility Requirements; Keyboard support, Screen reader support) · 10 Related · 11 References (WCAG, Nielsen Norman Group, Fluent, Material Design, Carbon). Components with a sibling that is not documented yet get a "To be added" note (`ds-desc ds-note`), never an empty heading. Some components need extra sections (for example Button: Sizes is bigger); add them after the closest standard one.

**Specifications: sections** Design Tokens · Sizes · Measurements · Elevation · States · Typography · Structure (Elements, Types, Width) · Motion · Behavior · Accessibility Requirements. Same rule: drop what the component does not have.

**Breakpoint control in the Playground.** A component whose values change at 769px gets a *Breakpoint* field (Window / Desktop / Mobile) in its Playground controls: `<div class="btn-group" data-bp-toggle data-bp-force>` and `DK.bp()` in the page script. `data-bp-force` makes `doc-kit.js` switch the `@media (min-width: 769px)` and `(max-width: 768px)` rules of the stylesheets in `components/css/` to "all" or "not all", so the real component CSS shows the Mobile or Desktop values whatever the window width (docs.css is never touched, so the docs layout follows the window). Window restores the real queries. No page-local copies of the values are needed. Skip the field when the component is the same at every breakpoint (Badge Dot). `DK.bp` still sets `body[data-bp]`, but no page copies component values behind it any more (Button and the Notifications were the last, converted 2026-10-13); the one demo rule is the Modal preview width, see Notifications above. `notifications.css` is forced too, with a virtual window width per value (Desktop 1280, Tablet 700, Mobile 375), because it has more breakpoints than 769px.

**Measurements** (Specifications, replaces the old Spacing section; the name follows Material, "Dimensions" alone would leave out padding). `h2` Measurements with two groups: **Dimensions** (a measurement figure plus an *Attribute / Value* table: padding per side, line height, height, max width, corners) and **Spacing** (the same padding and distances as spacing tokens, plain `h3` Padding / Beak and distance). The figure is the shared blueprint figure `components/css/measure.css` + `components/js/measure.js`: the real component at true size, 1:1 (`--k: 1`; set `style="--k:2"` on one `.measure` only when a component is too small to read) on a dotted grid, padding shaded with `surface-information-weak` (overlaps get deeper), dimension lines in `border-information-default`, numbers in `text-information-default` (blue = blueprint; tokens only). The script reads the padding from the real `.measure__subject`, so the numbers are live. A subject with a status edge outside its padding (toast, banner, inline) marks the edge `data-measure-edge` (on the subject itself it means its left border; on another element, that element's width): `measure.js` sets `--edge` and the left shading and the left dimension start after it. **Breakpoints:** when the component's padding changes at 769px (most components do), the figure has a *Breakpoint* toolbar (Window / Desktop / Mobile, `data-bp-toggle data-bp-force`, built in by the `measure_fig` helper of the generator, see the Playground control) and the page script calls `DK.bp(function () { ECO_MEASURE.init(); })`, so the figure re-measures the real component under the forced breakpoint (it also re-measures on window resize). A side with no padding is hidden. The table under the figure always lists both breakpoints. Leave the toolbar out when the values are the same everywhere (Tooltip). Markup per size: `.measure__item > .measure__name + .measure__obj` holding the subject (inside its own wrapper, e.g. `.tooltip-wrap`, so the component's variables apply), four `<i class="measure__pad measure__pad--t|b|l|r">` and four `<b class="measure__dim measure__dim--v|h measure__dim--t|b|l|r"><span></span></b>`; put the `.measure` in a `.ds-fig__stage` with `padding:0;min-height:0`. One item per size (Small, Large, …); a component with a fixed target size (checkbox: container 18, target 48, state layer 40) shows those as extra lines in the table. A component with no padding to draw (a divider) skips the figure and keeps the table.

## Motion section

When a component animates (close, open, enter, exit), give the page its own **Motion** section right after the playground, so the reader can compare easing and duration live. Use `DK.motion({ anchor, prefix, rec, why, collapse, preview })` from `eco-design-system/doc-kit.js` (Banner and Inline notification are the reference; `collapsible.html` and `segment-control.html` use `always: true` for previews with no close button). It builds the section (preview stage + controls, same layout as the playground), adds a "Motion" chip to the subnav and flips the background of the later sections so they keep alternating.

- Controls (sliders are the shared `eco-range` component: the page must link `/components/css/range.css` and `/components/js/range.js`): slider **Easing** (all four eco-motion easings), slider **Duration** (all 12 duration tokens, fast-1 … slow-4, tick labels in ms), **toggle button group** "Height" (Fade only / Collapse, `.ds-seg`; only with `collapse`) and Show again.
- `role: 'exit'` (component closes or is removed) adds a live warning under the controls and a table "Recommendations and warnings": Decelerate easing (made for enter, use Accelerate), Slow duration 450 ms or more (a closing element should leave quickly), Height Fade only (content jumps up). Other roles (enter, hover) need their own rules in `WARN` in `doc-kit.js` before use.
- Table "Motion for this selection": Property / Token / Value / Recommended, read live from the tokens.
- The component CSS reads `--<prefix>-ease` / `--<prefix>-duration` with the **recommended value as fallback**, and the JS skips the collapse inside `[data-<prefix>="fade"]`.
- `rec` = the recommended default for that component from `eco-motion` (combination rule: distance + fade + easing); `why` = one sentence. Recommended is marked `*`.
- Two motions on one page (Toast: enter + exit): pass `parts: [{ title, prefix, rec, exit }]` instead of `prefix`/`rec` (one Easing + Duration slider pair per part, `exit: true` gets the exit warnings) and `show()` instead of `preview()` for a component that is fixed in the window: the vars are set on `<html>` and the stage shows a hint plus a Show toast button. Reference: `components/toast.html`, `toast-ecom.html`.
- **Link to it from the playground and the code block.** `DK.motion` gives the section `id="motion"`. Add `<p class="pg-note" style="margin:0">The animation … is set in <a href="#motion" class="inline-link inline-link--small">Motion</a>.</p>` in the playground controls (before the Show/Show again button) and `<p class="ds-desc ds-note">The markup has no motion. … is set in <a href="#motion" class="inline-link inline-link--small">Motion</a>.</p>` under the code block. Reference: `banner.html`, `toast.html`, `toast-ecom.html`. No other element on the page may use `id="motion"` (name a spec table body `motion-rows`).
- When asked to build a component page for something that animates, **suggest** adding the Motion section (and the recommended default) before building it.


## Text fields in a playground

Playground text fields are the shared **`eco-input`**, never a docs-only style: `<div class="ds-field form-field"><label class="form-label" for="id">Label</label><div class="input-wrap"><div class="input-box"><input class="form-input" type="text" id="id" value="…" placeholder="Label" /></div></div></div>`, and the page links `/components/css/input.css`. The placeholder is required (the Active border uses `:placeholder-shown`). `subnav.js` sets `body.keyboard-nav` for the focus ring. Hover, active, focus and disabled then follow `eco-input` everywhere. `docs.css` has no text-input rules.

## Controls in a playground are the real components

Every control in a playground or toolbar is the shared component, never a docs-only style: option groups = the **button group** (`.btn-group`, joined System buttons, 2–4 options; link `/components/css/button-group.css`; see `eco-button`). The pill `eco-pill-segment-control` is not used in docs playgrounds, dropdowns = **`eco-select`** (`.form-select.form-select--sm` inside `.input-wrap`, plus `select.css`, `menu.css`, `select-menu.js`), text fields = **`eco-input`** (`.input-box--sm`), sliders = **`eco-range`**, single toggle buttons = **`eco-button`** (`btn btn--system btn--sm`). Field labels use `form-label form-label--sm`. Use the Small size. `docs.css` has no rules for these controls; fix the shared file instead.

**Which control (2026-11-08):** follow the playground table in `selection-guide`. On/off settings are Small **switches** (`eco-switch`, `build.sw_group`), one-of-many with longer labels or 4–7 options and every recurring field (State, Size, Value, Content, Type, Color, Variant, Status) are Small **radio buttons** (`eco-radio`, `build.radio_group`), short 2–3 option fields stay button groups, 8+ options a select. `gen/playground_rule.py` applies this to every generated page in `build.emit()`, so a generator may still call `btn_group` / `sel`; the page gets `radio.css` / `switch.css` linked automatically. `DK.wire` reads switches (`data-on` / `data-off`) and radio groups (`role="radiogroup"` with `data-pg`). Page JS that pokes a control must target the new markup (`input[data-pg="x"]`, `[data-pg="x"] input[value="…"]`), never `[data-pg="x"] button`.
